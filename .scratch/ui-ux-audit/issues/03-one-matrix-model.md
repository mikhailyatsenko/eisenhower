# Модель «одна матрица»

Type: grilling
Status: resolved

## Question

Направление принято: у пользователя одна матрица, её Storage определяется входом в аккаунт. Какое поведение при переходах?

- Вход, когда локальные задачи есть, а облако пустое: перенос автоматически или с предложением?
- Вход, когда задачи есть и там и там: слияние, выбор или игнор локальных?
- Что происходит с локальными задачами после переноса и после выхода из аккаунта?
- Что остаётся от переключателя Local/Cloud в меню аккаунта, отключённого `SwitchTaskSource` и кнопки «Copy all tasks to Cloud»?
- Как пользователь видит, где сейчас хранятся его задачи?

## Answer

У пользователя **одна матрица**. Где она хранится, определяет вход в аккаунт: анонимный — на устройстве, вошедший — в облаке. Выбора места хранения в интерфейсе нет.

- **Вход, облако пустое:** задачи автоматически переносятся в аккаунт, toast «12 задач перенесены в аккаунт» с Undo.
- **Вход, задачи есть и там и там:** один вопрос модалкой «Добавить N задач с этого устройства в аккаунт?» с кнопками «Добавить» и «Не добавлять». Молча не объединяем.
- **Перенос переносит, а не копирует:** локальная копия очищается. После выхода из аккаунта матрица пустая, с подсказкой «Ваши задачи в аккаунте, войдите, чтобы увидеть их».
- **Убираем:** переключатель Local/Cloud из меню аккаунта, мёртвый `SwitchTaskSource` вместе с обработкой `?cloud`, кнопку «Copy all tasks to Cloud». В меню аккаунта остаётся одна строка о месте хранения: «Сохраняется в аккаунте Google» или «Сохраняется только на этом устройстве».
- **Ошибка синхронизации:** матрица остаётся видимой, сверху полоска «Не удалось синхронизировать» с кнопкой «Повторить». Нельзя подменять всю матрицу красным текстом ошибки, как сейчас.

Замечания для реализации: сейчас копирование выдаёт задачам новые id и не чистит локальные (`copyLocalTasksToFirebaseAction`); при переносе нужно наоборот. В `useAuth` есть неиспользуемый вход через GitHub — в UI его нет, трогать не нужно.

Дополнено из [Офлайн для вошедшего пользователя](17-offline-ux.md): при Migration локальная копия очищается только после подтверждения сервером, а не сразу. «Sign out» при неотправленных правках предупреждает диалогом; после выхода кэш Firestore на устройстве стирается. «Повторить» в полосе ошибки заменено на «Reload» / «Sign in again», офлайн ошибкой не считается.

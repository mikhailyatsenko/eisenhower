# Мобильная матрица

Type: prototype
Status: resolved
Blocked by: 01, 02

## Question

Как должна выглядеть и вести себя матрица на телефоне? Сейчас квадранты — квадраты шириной в половину экрана, список задач скрыт до нажатия «Expand», заголовок квадранта 0.5rem, перенос задачи работает через long-press 300 мс, а подписи осей повёрнуты сбоку.

Прототип вариантов (например: текущая сетка с улучшениями, вкладки квадрантов, вертикальный список с группами) с учётом находок живого прохода и паттернов конкурентов.

Дополнено после живого прохода (`walkthrough.md`, раздел Mobile): матрица не показывает ни одной задачи, только счётчики и Expand, а половина экрана пустая; после Expand остальные квадранты ломаются (Expand вылезает за рамки, оси пропадают). Research: «Expand» не использует никто; есть два паттерна — сетка на весь экран со скроллом в ячейках или один квадрант плюс мини-матрица-переключатель.

## Answer

Прототип: ветка `prototype/mobile-matrix` (`d24587c`), на главной `?variant=current|A|B|C`. Скриншоты: `walkthrough/proto-06-{A,B,C}.png`.

**Выбран вариант A — сетка 2×2 на всю высоту экрана** для ширины < 640px (`sm`). Планшеты и desktop не меняются.

- Все 4 квадранта видны сразу вместе с задачами, кнопки «Expand» нет. Оси Urgent / Not urgent и Important / Not important остаются маленькими подписями.
- Заголовок ячейки показывает название квадранта, счётчик и «+» для добавления в этот квадрант. В пустой ячейке подсказка «Tap + to add».
- Карточки компактные: текст 12px, обрезка до 2 строк, дедлайн относительным бейджем («in 20 hours», «overdue 5 hours»). Дату создания на карточке не показываем.
- **Много задач:** ячейка скроллится внутри себя. Внизу заметный индикатор «+N ниже» вместо скрытого скроллбара. Тап по заголовку раскрывает квадрант на весь экран (как вариант B) с возвратом к матрице.
- **Перемещение:** основной способ — long-press drag, в A все цели на экране. «Переместить в» как запасной путь и поведение тапа по компактной карточке решает задача [Обнаружимость действий над задачей](05-task-actions-discoverability.md).

Почему A: он сохраняет всю матрицу одним взглядом, а это и есть продукт. B удобнее для чтения длинных задач, но прячет три квадранта. C теряет 2×2.

**Вариант C (секции подряд с липкими заголовками, критерии в заголовке, значок 2×2) пользователю понравился внешне.** Решено взять его за основу нового List view. Детали — в задаче [Роль List view](10-list-view-role.md).

## Comments

# Роль List view

Type: grilling
Status: resolved

## Question

Зачем пользователю List view, если есть матрица? Сейчас это та же лента карточек, квадрант виден только по цвету, сортировок две (дата создания / важность), сортировки по дедлайну нет, текст выровнен по центру. Варианты: убрать; превратить в «что делать сегодня» (сортировка по дедлайну и квадранту, группировка); оставить как мобильную альтернативу матрице (связано с задачей «Мобильная матрица»). Что выбираем и какие минимальные изменения это даёт?

Исходные данные из [Мобильная матрица](06-mobile-matrix.md): пользователь хочет, чтобы List view выглядел как вариант C прототипа (`prototype/mobile-matrix`, `?variant=C`, скриншот `walkthrough/proto-06-C.png`): секции по квадрантам в порядке приоритета, липкие заголовки «значок 2×2 + название + критерии + счётчик + “+”», сворачивание секций. Значит, List view остаётся. Открытые вопросы: нужны ли сортировки внутри секций (дедлайн? ручной порядок?) и как C выглядит на desktop.

Дополнено из [Обнаружимость действий над задачей](05-task-actions-discoverability.md): в матрице действия над задачей идут через выделение и панель действий. Нужно решить, работает ли List view так же (скорее да, ради единообразия).

## Answer

**List view — это та же матрица, прочитанная сверху вниз.** Он строится на варианте C из прототипа [Мобильная матрица](06-mobile-matrix.md) (`prototype/mobile-matrix`, `?variant=C`, `walkthrough/proto-06-C.png`) и работает одинаково на mobile и desktop.

**Структура.**
- Четыре секции в порядке приоритета: Do First, Schedule, Delegate, Eliminate. У каждой липкий заголовок: значок 2×2 с подсвеченной ячейкой, название, критерии подзаголовком, счётчик и «+».
- Секции сворачиваются. Какие секции свёрнуты, запоминается на устройстве.
- Пустая секция остаётся раскрытой и показывает тот же пример и CTA, что пустой квадрант по решению [Онбординг первого визита](08-first-visit-onboarding.md).
- На desktop всё идёт одной колонкой по центру (`max-w-2xl`). Текст задач выровнен по левому краю, это закрывает L3.

**Порядок.** Внутри секции задачи идут в том же порядке, что в квадранте матрицы. Select'ы «Sort by» / «Order» и сортировки Date / Importance убираются (закрывает L2 тем, что сортировок больше нет). Сортировку по дедлайну, если она понадобится, решает тема «Дедлайны и просрочка».

**Действия.** Всё как в матрице по решению [Обнаружимость действий над задачей](05-task-actions-discoverability.md): клик или тап выделяет задачу, снизу появляется панель Complete / Edit / Move to / Delete, работают те же клавиши. ↑↓ ходят по задачам сквозь границы секций, ←→ переходят к предыдущей или следующей секции. «+» в заголовке и клик по пустому месту секции открывают инлайн-поле добавления.

**Drag в списке нет.** Перенос между квадрантами идёт через «Move to», ручной порядок меняется только в матрице. Причины: в длинном скроллящемся списке drag неудобен, а на телефоне конфликтует со скроллом.

**Переключение вида.** При переходе Matrix ↔ List скролл сбрасывается наверх (закрывает L4). Выбранный вид запоминается на устройстве. По умолчанию, в том числе на телефоне, открывается Matrix. Completed показывается под списком так же, как под матрицей.

**Почему так.** У двух видов одна модель и один порядок, поэтому пользователю не нужно ничего переучивать. Квадрант обозначен подписью и значком, а не только цветом, это закрывает L1. Сортировки, которые новичок не заметил бы, из UI уходят.

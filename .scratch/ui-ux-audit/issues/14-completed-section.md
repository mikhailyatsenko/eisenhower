# Блок Completed

Type: grilling
Status: resolved

## Question

Завершённые задачи живут в блоке Completed под матрицей. Находки [прохода](../walkthrough.md): M7 (в первом экране виден только край блока), C3 (от старых к новым, свежая задача внизу), C4 (при открытии страница сама скроллится, Restore и Delete видны только при hover, дата создания спрятана за hover).

После решений [Мобильная матрица](06-mobile-matrix.md) (матрица на всю высоту экрана), [Обнаружимость действий](05-task-actions-discoverability.md) (выделение + панель действий) и [Единая модель деструктивных действий](04-destructive-actions.md) (Undo вместо confirm):

- Где Completed живёт, если под матрицей на mobile места нет: под матрицей, в шапке, в List view, отдельный экран?
- Порядок и объём: новые сверху, лимит или группировка по дням, автоочистка?
- Как действуют Restore и Delete: через ту же модель «выбери, потом действуй» или отдельно?
- Показывать ли, из какого квадранта задача, и куда её возвращает Restore?

## Answer

| Вопрос | Решение |
|---|---|
| Где живёт | **Последняя секция List view** «Completed (N)», по умолчанию свёрнута, свёрнутость запоминается, как у остальных секций ([Роль List view](10-list-view-role.md)). В Matrix под матрицей одна строка «✓ N completed →», она открывает List view сразу на этой секции. Если завершённых нет, строки и секции нет. Автоскролл при раскрытии убирается. |
| Порядок и объём | **Новые сверху**, без группировки по дням. Первые 50, дальше «Show more». Автоочистки нет. |
| Действия | **«Выбери, потом действуй»**, как в матрице ([Обнаружимость действий](05-task-actions-discoverability.md)): тап или клик выделяет завершённую задачу, снизу панель **Restore / Delete**. Delete сразу, с Undo-toast, без `window.confirm` ([Единая модель деструктивных действий](04-destructive-actions.md)). Delete/Backspace удаляют выделенную; клавиши 1–4 здесь не действуют. «Delete all» — в заголовке секции, с модальным диалогом. Иконки только по hover уходят. |
| Исходный квадрант | Подпись с именем квадранта (Do First / Schedule / Delegate / Eliminate) на строке; приглушённый цвет остаётся только дополнительным признаком ([Минимальная планка доступности](11-accessibility-baseline.md)). |
| Куда Restore | В исходный квадрант, **в начало**: восстановленная задача снова актуальна и должна быть видна. |
| Toast на Restore | Restore считается разновидностью Move: toast «Restored to Schedule» с Undo. Дополняет список в [Поведении toast-уведомлений](12-toast-behaviour.md). |
| Даты | Только дата завершения, в формате, который выберет [Дедлайны и просрочка](15-deadlines-overdue.md). Дату создания не показываем совсем. |

Отклонено: третий сегмент Completed в шапке (пересматривает [Шапку и навигацию](07-header-navigation.md) ради редкого сценария), блок под матрицей на всех ширинах (на mobile под полноэкранной матрицей его не видно), группировка по дням, автоочистка старых задач.

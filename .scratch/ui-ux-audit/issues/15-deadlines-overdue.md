# Дедлайны и просрочка

Type: prototype
Status: resolved

## Question

Дедлайн — единственная метаданная на карточке ([Обнаружимость действий](05-task-actions-discoverability.md)). Сейчас: формат `dd/MM/yyyy HH:mm` без относительного времени, у просроченных красное кольцо, в форме одно поле даты-времени, datepicker на mobile не проверен ([каталог прохода](../walkthrough.md), «Не пройдено»). По [Минимальной планке доступности](11-accessibility-baseline.md) цвет не может быть единственным признаком.

- Формат на карточке: абсолютный, относительный («завтра», «через 3 дня») или оба; локаль и 12/24 часа.
- Как выглядят «скоро» и «просрочено» без опоры только на цвет.
- Форма: дата и время раздельно, время необязательно, быстрые варианты (сегодня, завтра, через неделю), нативный `<input type="date">` на mobile или текущий datepicker.
- Влияет ли дедлайн на порядок задач в квадранте или на подсказку перенести задачу (Schedule → Do First)?
- Тот же формат даты используется для даты завершения в секции Completed ([Блок Completed](14-completed-section.md)).

## Answer

Прототип: ветка `prototype/deadlines` (`d0b4166`), `?variant=current|A|B|C`, скриншоты `walkthrough/proto-15-*.png`. Выбраны карточка из варианта B, форма из варианта A, порядок задач не меняется.

**Карточка: всегда абсолютная дата и текстовый бейдж статуса.**

- Формат: день недели, число, месяц (`Fri 25 Sept, 9:00`). Год только если он не текущий (`Fri, 29 Oct 2027`). Время только если пользователь его задал. Локаль и 12/24 часа берутся из браузера (`toLocaleDateString` / `toLocaleTimeString`), а не зашиты как `dd/MM/yyyy HH:mm`.
- Статус: бейдж словом перед датой. `⚠ OVERDUE` (срок прошёл), `DUE TODAY` (сегодня), `DUE SOON` (завтра и послезавтра). Дальше бейджа нет, только дата. Статус читается по тексту, цвет лишь усиливает его (у OVERDUE заливка и толстая левая полоса у карточки), поэтому требование [Минимальной планки доступности](11-accessibility-baseline.md) выполнено. Красное кольцо `ring-red-500` уходит.
- Дата создания с карточки убирается (M1 из прохода): на карточке только текст и дедлайн, как решено в [Обнаружимости действий](05-task-actions-discoverability.md).

**Форма: быстрые чипы и нативные поля, время необязательно.**

- Чипы: No deadline / Today / Tomorrow / This weekend / Next week. Каждый ставит дату без времени.
- Ниже нативный `<input type="date">` и кнопка «+ Add time», которая открывает нативный `<input type="time">` с «Remove time». На телефоне это системные пикеры, поэтому вопрос «datepicker на mobile не проверен» снимается. `react-datepicker` и пресеты +3h / +24h / +3d / +1w уходят.
- Дедлайн без времени означает «до конца дня»: просроченным он становится после 23:59 этого дня. В модели `Task` нужен признак «время задано», иначе дату без времени нельзя отличить от 23:59. Под полями строка-превью «Shows on card as: …».

**Дедлайн не влияет на порядок.** Порядок в квадранте ручной, как в матрице и List view ([Роль List view](10-list-view-role.md)). Автоподъёма просроченных и подсказки «Move to Do First» нет: квадрант задаёт пользователь, приложение ему не перечит.

**Completed** использует тот же формат без бейджа: `Completed Thu 24 Sept, 8:30` ([Блок Completed](14-completed-section.md)).

## Comments

Прототип: ветка `prototype/deadlines` (`d0b4166`), главная с `?variant=current|A|B|C`. Образцы задач покрывают все статусы (просрочено, сегодня, скоро, позже, без дедлайна, другой год), клик по карточке выбирает задачу, панель справа меняет её дедлайн. В розовой панели переключается локаль (en-GB / en-US / de-DE / ru-RU). Скриншоты: `walkthrough/proto-15-A-desktop.png`, `proto-15-A-mobile.png`, `proto-15-B-desktop.png`, `proto-15-C-desktop.png`.

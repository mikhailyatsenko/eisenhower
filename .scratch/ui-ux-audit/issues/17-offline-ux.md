# Офлайн для вошедшего пользователя

Type: grilling
Status: resolved
Blocked by: 16

## Question

[Модель «одна матрица»](03-one-matrix-model.md) отдаёт вошедшему пользователю облако без локальной копии, а ошибка синхронизации — полоса с «Retry» под шапкой ([Шапка и навигация](07-header-navigation.md)). С учётом фактов из [Как ведёт себя облачная матрица без сети](16-firestore-offline-research.md):

- Нужна ли вошедшему пользователю работа без сети (правки копятся и уходят позже) или достаточно честной ошибки?
- Что видно в UI: признак «не синхронизировано», когда полоса ошибки, а когда тихое ожидание.
- Что с Undo-toast, если запись ещё не ушла в облако.
- Холодный старт без сети: пустая матрица, кэш или сообщение.

## Answer

**Вошедший пользователь без сети работает так же, как анонимный: правки применяются сразу и уходят в облако, когда появится сеть. Главное, чтобы он видел, что сейчас офлайн.**

| Вопрос | Решение |
|---|---|
| Режим | **Полноценный офлайн.** `persistentLocalCache` + `persistentMultipleTabManager`: очередь правок и кэш матрицы в IndexedDB, переживают перезагрузку. Честная ошибка с read-only матрицей и офлайн только в пределах вкладки отклонены: вход в аккаунт не должен делать приложение хуже анонимного. |
| Живое обновление | Облачная матрица читается живой подпиской (`onSnapshot` с `includeMetadataChanges`), а не одним `getDocs`. Правки с других вкладок и устройств применяются молча, без уведомления; если выделенная задача исчезла, выделение снимается. |
| Индикация офлайна | **Одна полоса под шапкой, два тона.** Нейтральный, `role="status"`, без кнопки: «You're offline. Changes are saved on this device and will sync when you're back online.» Показывается сразу при `navigator.onLine === false` и при «lie-fi» (правки не подтверждены дольше ~10 с). Сеть вернулась, правки ещё уходят: «Syncing…»; после подтверждения ~2 с «All changes saved», затем полоса исчезает. Значок на аватаре отклонён: новичок его не заметит, на touch нет tooltip. |
| Ошибка синхронизации | Это только **отказ сервера** (правила, квота, истёкшая сессия), не отсутствие сети. Красный тон, `role="alert"`: «Some changes couldn't be saved to your account.» с кнопкой «Reload» (заново подтянуть матрицу с сервера); при истёкшей сессии — «Sign in again». Откаченная правка просто исчезает, перечня не храним. |
| Undo | Не зависит от сети: отмена — ещё одно локальное действие, toast тот же, без пометки «not synced». |
| Холодный старт без кэша | Матрица показывается с полосой офлайна; вместо онбординга первого визита текст «Your tasks are in your account. They'll appear when you're back online.» Отличаем по `fromCache` первого снимка. Добавлять задачи можно. Пустая матрица молча больше не показывается. |
| Выход из аккаунта | При неотправленных правках «Sign out» открывает диалог «N changes aren't saved to your account yet. If you sign out now, they'll be lost.» — «Stay signed in» / «Sign out anyway». После выхода кэш Firestore стирается всегда (`terminate` + `clearIndexedDbPersistence`); вопрос «доверяете ли устройству» не задаём. |
| Закрытие вкладки | Есть неотправленные правки — браузерное предупреждение `beforeunload`, в любом режиме кэша (откат SDK на memory cache в Firefox Private и при переполнении квоты не отличаем). |
| Migration | Локальная копия очищается **только после подтверждения сервером** (`waitForPendingWrites`); до этого задачи видны в облачной матрице из кэша, полоса показывает офлайн или «Syncing…». Toast Migration с Undo появляется сразу. Худший случай — дубликат на устройстве, но не потеря. |

Замечания для реализации: стор больше не ждёт промисов записи (форма добавления закрывается сразу, повторный Enter не плодит дубли); «Clear all» удаляет по id из снимка, а не повторным `getDocs` из кэша.

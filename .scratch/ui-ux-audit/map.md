# UI/UX-аудит

Label: wayfinder:map

## Destination

Спека UX-изменений: приоритизированный список проблем UI/UX, по каждой принято решение, как исправлять. Готова к нарезке на implementation-тикеты.

## Notes

- Главный пользователь: новичок с первого визита (SEO-трафик на howereisen.com), анонимный, с локальным хранением, mobile и desktop. Постоянный залогиненный пользователь идёт вторым приоритетом.
- В scope: удобство основных сценариев (добавить, переместить, изменить, завершить, удалить задачу), мобильная версия, доступность, тексты и онбординг.
- Выводы основываются на коде и живом проходе в браузере (`npm run dev`, desktop и mobile viewport). Данных GA не будет, решения принимаются по здравому смыслу.
- Направление по хранению принято при картировании: **одна матрица**, её Storage зависит от входа в аккаунт. Детали решает задача [Модель «одна матрица»](issues/03-one-matrix-model.md).
- Словарь: `CONTEXT.md`. Для grilling-задач вызывать скиллы `grilling` и `domain-modeling`, для prototype-задач вызывать `prototype`.

## Decisions so far

- [Как другие Eisenhower-приложения решают мобильную матрицу и онбординг](issues/02-competitor-research.md): за «Expand» задачи никто не прячет. Паттерны: сетка 2×2 на весь экран со скроллом в ячейках или один квадрант плюс мини-матрица-переключатель; меню «переместить в» как альтернатива long-press drag; выбор квадранта в форме; вместо модалки подсказки в пустых квадрантах. Веб-матрицы без регистрации у конкурентов нет.
- [Живой проход ключевых сценариев](issues/01-live-walkthrough.md): найдено 2 бага, портящих данные, на mobile матрица не показывает задач, в UI три словаря названий квадрантов, действия и вставка плохо заметны, удаление и перемещение устроены непоследовательно; каталог в [walkthrough.md](walkthrough.md).
- [Единый словарь названий квадрантов](issues/09-quadrant-vocabulary.md): имя квадранта — действие (Do First / Schedule / Delegate / Eliminate), критерии — подзаголовок по шаблону «важность, потом срочность», показываются в форме; в матрице их дают оси.
- [Мобильная матрица](issues/06-mobile-matrix.md): на экранах < 640px сетка 2×2 на всю высоту экрана, задачи видны сразу, без Expand; много задач — скролл в ячейке с индикатором «+N» и тап по заголовку для полноэкранного квадранта; перемещение long-press drag. Вид «секции подряд» (вариант C) уходит в List view.
- [Модель «одна матрица»](issues/03-one-matrix-model.md): матрица одна, хранение определяется входом в аккаунт; при входе задачи переносятся (с Undo, а при непустом облаке — с одним вопросом) и локальная копия очищается; переключатель Local/Cloud, `?cloud` и «Copy to Cloud» убираются; ошибка синхронизации — полоска с «Повторить», а не подмена матрицы.
- [Единая модель деструктивных действий](issues/04-destructive-actions.md): отмена вместо подтверждения — удаление задачи и перемещение между квадрантами идут через toast с Undo (6 с), `window.confirm` уходит совсем, подтверждение остаётся только у «delete all» и становится своим модальным диалогом.
- [Обнаружимость действий над задачей](issues/05-task-actions-discoverability.md): «выбери, потом действуй» — на карточке только текст и дедлайн, клик или тап выделяет задачу, снизу панель Complete / Edit / Move to / Delete с клавишами (1–4 без выделения добавляют, с выделением переносят); добавление кликом по пустому месту любого квадранта, `InsertTaskZone` уходит.
- [Шапка и навигация](issues/07-header-navigation.md): вариант A — шапка во всю ширину: логотип (название от `md`), сегменты Matrix | List, тема с доступным именем, «Sign in» или аватар с меню (место хранения, выход); ошибка синхронизации — полоса под шапкой с «Retry»; градиент и угловые иконки уходят.
- [Онбординг первого визита](issues/08-first-visit-onboarding.md): welcome-модалку и демо-задачи убираем. В пустом квадранте пример + CTA, «click empty space to add» пропадает после первого использования, строка «select» под матрицей видна всегда (мышь или touch определяются по указателю, не по ширине). Над пустой матрицей строка «No sign-up», на главной постоянный серверный `h1`, объяснение метода на индексируемой странице `/eisenhower-matrix` со ссылками из пустой матрицы, `?` и футера.
- [Роль List view](issues/10-list-view-role.md): List view остаётся — та же матрица сверху вниз. Секции по квадрантам в порядке приоритета, липкие заголовки со значком 2×2, сворачивание запоминается. Порядок задач как в матрице, select'ы сортировки уходят. Выделение, панель действий и клавиши как в матрице, drag нет. На desktop одна колонка с текстом по левому краю.
- [Минимальная планка доступности](issues/11-accessibility-baseline.md): WCAG 2.2 AA для основных сценариев. Квадрант — `listbox`, фокус совпадает с выделением, матрица — одна остановка Tab; клавиатурного drag нет, порядок внутри квадранта — осознанное исключение из 2.5.7; нативный `<dialog>`, тёмный текст на цветах квадрантов, цели 44×44, `jest-axe` плюс ручной проход с VoiceOver.
- [Поведение toast-уведомлений](issues/12-toast-behaviour.md): toast только на Complete, Delete, Move и Migration (добавление и правка молча); один за раз снизу над панелью действий, новый заменяет старый; 6 с с паузой на hover, фокус, уход со вкладки и касание, Migration висит до первого действия; без крестика, `Ctrl/Cmd+Z` и `role="status"`; error-toast убирается.
- [Что Analytics даёт новичку](issues/13-analytics-value.md): Analytics убирается целиком вместе с кнопкой в шапке и Alt+S; совет о балансе квадрантов переезжает текстом на `/eisenhower-matrix`.
- [Как ведёт себя облачная матрица без сети](issues/16-firestore-offline-research.md): сейчас memory cache без подписок; записи без сети ждут в очереди в памяти без таймаута и теряются при перезагрузке, стор оптимистичный без отката и индикации, офлайн-загрузка показывает пустую матрицу; `persistentLocalCache` + multi-tab хранят очередь в IndexedDB, статус дают `hasPendingWrites`/`fromCache` и `waitForPendingWrites` ([research](research/firestore-offline.md)).
- [Блок Completed](issues/14-completed-section.md): последняя свёрнутая секция List view, из Matrix — строка «✓ N completed →»; новые сверху, 50 и «Show more», без автоочистки; «выбери, потом действуй» с панелью Restore / Delete (Undo вместо confirm); подпись исходного квадранта, Restore возвращает в начало квадранта с toast; только дата завершения.
- [Дедлайны и просрочка](issues/15-deadlines-overdue.md): на карточке абсолютная дата в локали браузера (год и время только если нужны) и бейдж словом OVERDUE / DUE TODAY / DUE SOON вместо красного кольца; в форме чипы Today / Tomorrow / This weekend / Next week, нативные date и необязательный time (без времени = до конца дня), `react-datepicker` уходит; на порядок задач дедлайн не влияет.
- [Офлайн для вошедшего пользователя](issues/17-offline-ux.md): полноценный офлайн на `persistentLocalCache` и живой подписке; под шапкой одна полоса — нейтральная «You're offline…» / «Syncing…» / «All changes saved» и красная только при отказе сервера («Reload» или «Sign in again»); Undo от сети не зависит; холодный старт без кэша — сообщение вместо онбординга; выход и закрытие вкладки предупреждают о неотправленных правках, кэш при выходе стирается; Migration чистит локальную копию только после подтверждения сервером.
- [Шкала серьёзности и порядок в спеке](issues/18-severity-prioritization.md): три уровня (S1 — сценарий новичка сломан или теряются данные, S2 — путает или нарушает AA, S3 — полировка); 16 срезов поставки в четырёх релизах (R1 новичок справляется, R2 вошедший не теряет правки, R3 всё понятно, R4 полировка); a11y — сквозной критерий приёмки. Итог — [spec.md](spec.md).

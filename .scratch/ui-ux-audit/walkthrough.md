# Живой проход: каталог находок

Как проходили: `npm run dev`, чистый профиль Chrome, тёмная системная тема. Для заполненной матрицы использовали тестовые задачи, подложенные в `localStorage`. Скриншоты лежат в `walkthrough/`. Серьёзность не проставлена, это решит финальная приоритизация.

Метки: **[код✓]** — находка из кода подтвердилась вживую, **[новое]** — видно только вживую.

## 🐞 Баги (вне UX-спеки, чинить отдельно и сразу)

- **B1. Правка задачи молча переносит её в Eliminate.** [новое] Открываем Edit у задачи из Do First: в форме выбран квадрант «Not Urgent & Not Important», хотя фон модалки красный. Меняем текст, жмём Save. Задача уезжает в конец Eliminate, за пределы видимой области, а toast говорит только «Task successfully updated». Причина: у задач, созданных через `addTaskAction`, нет `quadrantKey`, а `EditTaskForm` берёт `task.quadrantKey || 'NotImportantNotUrgent'`. Под удар попадает каждая правка любой задачи, созданной через UI. Скриншоты: `d09-edit-modal.png`, `d11-edit-no-deadline.png`, `d12-edit-moved-to-eliminate.png`.
- **B2. Редактирование задачи с дедлайном после перезагрузки падает.** [новое] Save закрывает модалку, но ничего не сохраняется, а Next показывает «1 error». Причина: `persist` в `useTaskStore` не превращает `dueDate` и `createdAt` обратно в `Date`, и `task.dueDate?.getTime()` в `editTaskAction` бросает исключение. Для облачных задач `lib` даты разбирает, для локальных нет. Скриншот: `d10-after-edit-enter.png`.

## Первый визит

- **F1.** GET STARTED не запоминает, что пользователь закрыл модалку, и она появляется при каждом визите. Не показывать её снова можно только через «Don't Show This Again». [код✓] `d01-first-visit.png`
- **F2.** Модалка — стена текста: три абзаца, четыре карточки, pro-tip. Она перекрывает пустую матрицу, которая сама по себе и есть лучшее объяснение метода. У конкурентов модалок нет (см. research).
- **F3.** Пустой квадрант показывает огромное «0 tasks» и ничего не говорит о том, что по нему можно кликнуть и добавить задачу. [новое] `d02-empty-matrix.png`
- **F4.** Кнопка аккаунта — «G» в полукруге в левом верхнем углу, без подписи. Что это вход и выбор места хранения, не понятно. [новое]

## Карточка задачи и матрица

- **M1.** Самая заметная строка метаданных на карточке — дата создания (`21/09/2026 11:46`, жирный курсив). Для приоритизации она почти бесполезна и визуально спорит с дедлайном. [новое]
- **M2.** Скроллбар в квадранте скрыт (`scrollbar-hidden`). Задачи, которые не влезли, обрезаются по краю без подсказки: в Eliminate из 7 задач видно 4,5. [новое] `d05-full-matrix.png`
- **M3.** Кнопки complete / edit / delete видны только при наведении, мелкие (18px) и серые. Клик и двойной клик по самой задаче ничего не делают. [код✓] `d06-hover-task.png`
- **M4.** Зоны вставки между задачами — еле видные линии толщиной 1px. [код✓]
- **M5.** Когда задачу тащат над квадрантом, он заливается `bg-gray-400`, и в тёмной теме текст задач становится почти нечитаемым. [новое] `d07-after-drag.png`
- **M6.** Перемещение drag'ом нельзя отменить: toast есть у добавления, завершения и правки, а у перемещения нет. [новое] `d08-after-drop.png`
- **M7.** Под матрицей в первом экране виден только край блока Completed (полоска внизу), поэтому о нём легко не узнать. [новое]

- **L4.** После переключения в List view страница остаётся на старой позиции скролла (открылась в середине списка). [новое] `d16-list-view.png`

## Доступность (из a11y-дерева)

- **X1.** У кнопки аккаунта нет доступного имени (`button` без label). Кнопку темы нет в a11y-дереве вообще. [новое]
- **X2.** Карточка задачи — `role=button` (dnd-kit), а внутри неё вложены ещё кнопки и ссылки. Интерактивные элементы внутри интерактивного — нарушение. [новое]
- **X3.** Перетаскивание с клавиатуры в dnd-kit есть (Space + стрелки, инструкция на английском в `aria-description`), но визуально его ничто не выдаёт. [новое]
- **X4.** Модалки не размечены как `dialog`, фокус не ловится внутри модалки. [код✓]
- **X5.** Кнопки действий с `opacity-0` недоступны без наведения, их не удаётся кликнуть даже программно. [новое]

## Mobile (390×844, touch)

- **P1. Матрица на телефоне не показывает ни одной задачи.** Видны 4 квадранта с огромными полупрозрачными «2 tasks» и кнопками Expand, а нижняя половина экрана пустая. Чтобы увидеть хоть одну задачу, нужен лишний тап. [код✓] `m02-mobile-matrix.png`
- **P2.** После Expand три остальных квадранта сжимаются в узкие ячейки. Кнопки Expand в них вылезают за рамки, видны серые полосы скроллбаров, подписи осей Urgent/Important пропадают. [новое] `m03-mobile-expanded.png`
- **P3.** Кнопка «Collapse Quadrant» — серая полоса внизу квадранта, в светлой теме с блеклым текстом. [новое]
- **P4.** FAB «New task» перекрывает кнопки complete / edit / delete у карточки под собой. Отступа снизу под FAB нет. [новое] `m01-mobile-matrix.png`
- **P5.** Меню аккаунта — полупрозрачный «пузырь» на пол-экрана поверх задач. Задачи просвечивают сквозь текст, кнопки закрытия нет. Сам текст про хранение понятный: «stored only on this device», «sign in with Google». [новое] `m05-account-menu.png`
- **P6.** Long-press drag не проверен: эмуляция touch через MCP ненадёжна. Из кода: задержка 300 мс, альтернативы нет.

## Не пройдено

- long-press drag на реальном touch-устройстве;
- выбор даты в datepicker на mobile;
- меню аккаунта после входа, переключение Cloud/Local (нужен логин, это часть задачи «Модель „одна матрица“»).

Инструмент: Chrome DevTools MCP дважды зависал (нативный `confirm` блокирует CDP; «Target closed»). Для последующих прототипов стоит подменять `window.confirm` через `initScript`.

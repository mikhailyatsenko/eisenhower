# 01: jest-axe, главный тестовый seam и ручной чек-лист

**What to build:** Разработчик может смонтировать главную с заранее засеянной **Matrix** (Storage на устройстве), действовать через user-event и проверять доступность через `jest-axe`. Этой проверкой пользуется каждый следующий тикет R1. Ручной чек-лист клавиатуры и VoiceOver лежит в репозитории. Срез A [спеки R1](../spec.md), решение: [Минимальная планка доступности](../../ui-ux-audit/issues/11-accessibility-baseline.md).

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] `jest-axe` подключён к существующему jest (jsdom, SWC через `next/jest`), матчер зарегистрирован в setup-файле.
- [x] Есть общий помощник тестов: монтирует `HomePage` с задачами, засеянными в localStorage до монтирования, с реальным DndContext. Мокаются только внешние границы: конфиг Firebase и `matchMedia` (указатель `(hover: none) and (pointer: coarse)` и ширина < 640px переключаются из теста).
- [x] Axe-проверка главной проходит. Уже известные нарушения — X1 (безымянная кнопка аккаунта) и X2 (вложенные интерактивные элементы в карточке) — записаны как явные исключения по правилу axe с кодом находки. Любое новое нарушение валит тест.
- [x] Ручной чек-лист лежит markdown-файлом рядом с документацией для агентов. Основные сценарии (добавить, изменить, завершить, удалить) проходятся сначала только клавиатурой, затем VoiceOver на macOS и на iOS. В начале файла сказано, что каждый срез дописывает свои сценарии.
- [x] Существующие тесты зелёные.

# 04: Подписанная кнопка аккаунта

**What to build:** Анонимный пользователь видит в углу кнопку с подписью «Sign in» и значком Google, а не безымянную «G». Кнопку находит и screen reader. Шапка целиком переделывается в R3 (срез L), здесь только подпись и доступное имя. Срез C [спеки R1](../spec.md), решение: [Шапка и навигация](../../ui-ux-audit/issues/07-header-navigation.md). Частично закрывает F4 и X1.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] У анонимного пользователя кнопка аккаунта — настоящий `button` с видимым текстом «Sign in» и значком Google.
- [ ] У вошедшего пользователя аватар-кнопка с доступным именем по имени аккаунта. Остальное поведение меню не меняется.
- [ ] Контраст подписи не меньше 4.5:1 в обеих темах.
- [ ] Axe-исключение X1 для кнопки аккаунта снято. Кнопку темы тикет не трогает: её `aria-label` придёт в срезе L.
- [ ] Тест на главном seam: `getByRole('button', { name: 'Sign in' })`.

## Comments

**Из тикета 01.** Исключения X1 «для кнопки аккаунта» в `src/app/tests/axe.ts` нет и снимать нечего: аккаунт сейчас `<div>`, axe его не видит. Исключение `button-name` (X1, `nodes: 1`) относится к кнопке темы и остаётся до среза L. Когда аккаунт станет `button` с именем «Sign in», число безымянных кнопок не вырастет, и axe-тест останется зелёным. Если у новой кнопки не будет имени, узлов станет два и тест упадёт. Этот пункт закрывает проверка через `getByRole`.

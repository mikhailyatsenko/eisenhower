# 04: Подписанная кнопка аккаунта

**What to build:** Анонимный пользователь видит в углу кнопку с подписью «Sign in» и значком Google, а не безымянную «G». Кнопку находит и screen reader. Шапка целиком переделывается в R3 (срез L), здесь только подпись и доступное имя. Срез C [спеки R1](../spec.md), решение: [Шапка и навигация](../../ui-ux-audit/issues/07-header-navigation.md). Частично закрывает F4 и X1.

**Blocked by:** 01

**Status:** resolved

- [x] У анонимного пользователя кнопка аккаунта — настоящий `button` с видимым текстом «Sign in» и значком Google.
- [x] У вошедшего пользователя аватар-кнопка с доступным именем по имени аккаунта. Остальное поведение меню не меняется.
- [x] Контраст подписи не меньше 4.5:1 в обеих темах.
- [x] Axe-исключение X1 для кнопки аккаунта снято. Кнопку темы тикет не трогает: её `aria-label` придёт в срезе L.
- [x] Тест на главном seam: `getByRole('button', { name: 'Sign in' })`.

## Comments

**Из тикета 01.** Исключения X1 «для кнопки аккаунта» в `src/app/tests/axe.ts` нет и снимать нечего: аккаунт сейчас `<div>`, axe его не видит. Исключение `button-name` (X1, `nodes: 1`) относится к кнопке темы и остаётся до среза L. Когда аккаунт станет `button` с именем «Sign in», число безымянных кнопок не вырастет, и axe-тест останется зелёным. Если у новой кнопки не будет имени, узлов станет два и тест упадёт. Этот пункт закрывает проверка через `getByRole`.

**Итог (ветка `ux-r1`).**
- Закрытое состояние `BubbleCornerButton` теперь настоящий `<button>`. Раньше это был кликабельный `div`. У кнопки новый проп `closedLabel` (`aria-label` для содержимого без текста) и видимое кольцо фокуса. Пока кнопка уехала за край при прокрутке, на обёртке стоит `inert`, и Tab на неё не попадает. Форма закрытого состояния: вместо четверти круга скруглённый прямоугольник `rounded-br-3xl`, иначе подпись обрезалась бы. Открытая панель по-прежнему круг.
- `AuthIndicator`: анонимно в кнопке значок Google (`aria-hidden`, `fill-current`) и текст «Sign in». Вошедшему — аватар с доступным именем `displayName`, запасное имя «Account». Меню не менялось.
- Контраст подписи: gray-900 на indigo-200 и gray-100 на indigo-950, оба с большим запасом выше 4.5:1. Проверено скриншотами headless Chrome в обеих темах.
- Тест на главном seam — `src/app/tests/accountButton.test.tsx`: `getByRole('button', { name: 'Sign in' })`, подпись — видимый текст, `Enter` открывает панель входа. До правки оба теста падали. Компонентный тест `AuthIndicator` переведён с `data-testid` на роли, в него добавлена проверка имени аватар-кнопки. Axe-исключения для аккаунта не было, как и записано в комментарии тикета 01. `button-name` (X1, 1 узел — кнопка темы) остаётся до среза L, комментарий в `axe.ts` поправлен.
- В `docs/agents/a11y-checklist.md`, раздел C, дописан сценарий кнопки аккаунта.
- Долг для среза L: после `Enter` кнопка размонтируется и фокус падает на `body`, `Esc` фокус не возвращает. Это старое поведение меню, по тикету оно не меняется.
- Все 11 наборов jest зелёные (30 тестов), tsc и eslint чистые. Ревью (standards + spec) нарушений не нашло; по его замечаниям добавлен `inert` и убрано дублирование ветвления в `AuthIndicator`.

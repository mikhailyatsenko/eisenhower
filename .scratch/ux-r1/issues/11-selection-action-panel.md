# 11: Выделение и панель действий (мышь и тап)

**What to build:** Карточка в матрице — только текст и дедлайн. Клик или тап выделяет задачу, и снизу появляется панель с подписанными кнопками Complete, Edit, Move to, Delete. Все действия проходят через Undo. Срез F [спеки R1](../spec.md), решения: [Обнаружимость действий над задачей](../../ui-ux-audit/issues/05-task-actions-discoverability.md) (primary source — ветка `prototype/task-actions`, вариант B), [Минимальная планка доступности](../../ui-ux-audit/issues/11-accessibility-baseline.md). Закрывает M3, X2, X5, M1.

**Blocked by:** 10

**Status:** resolved

- [x] **Selected Task** — одно состояние в UI-сторе: id задачи или ничего. Одновременно выделена не больше одной задачи.
- [x] Карточка матрицы: текст и относительный бейдж дедлайна, без иконок, ссылок-действий и даты создания. URL в тексте показываются обычным текстом, без `Linkify`.
- [x] Квадрант — `listbox` с доступным именем по названию квадранта, задача — `option` с `aria-selected`.
- [x] Клик или тап выделяет задачу, кольцо выделения контрастнее 3:1 в обеих темах. Повторный клик, клик по пустому месту квадранта или Esc снимают выделение. **Переходное решение до среза G:** клик по пустому месту пустого квадранта по-прежнему открывает форму добавления.
- [x] Панель — `role="toolbar"` с подписью «Actions for “<текст задачи>”», внизу окна, пока есть выделение. Кнопки Complete, Edit, Move to (четыре квадранта по названию, текущий неактивен), Delete. Появление панели не объявляется.
- [x] Complete, Delete и Move to идут через слот отмены (тикеты 07 и 09). Edit открывает обычную форму правки. После Complete, Delete и Move выделение переходит на следующую задачу квадранта, если её нет — на предыдущую.
- [x] Toast стоит прямо над панелью, без панели — у нижнего края.
- [x] Drag мышью стартует после сдвига на несколько пикселей (activation distance), клик выделяет. Long-press на touch не меняется (300 мс, tolerance 10). `KeyboardSensor` dnd-kit удалён. Блокирование drag через `data-no-dnd` для кнопок карточки убрано.
- [x] **Переходное решение до среза N:** List view сохраняет карточку с кнопками complete, edit, delete, видимыми всегда, без `opacity-0`. Действия идут через слот отмены. Общие у карточек матрицы и List view только текст и бейдж дедлайна.
- [x] Axe-исключение X2 снято.
- [x] Тесты на главном seam: клик выделяет (`aria-selected="true"`) и показывает toolbar с именем; Move to и Complete из панели дают toast и переводят выделение; в карточке матрицы нет вложенных кнопок; List view по-прежнему удаляет и завершает.
- [x] В ручной чек-лист добавлены выделение и панель.

## Comments

**Итог (ветка `ux-r1`).**
- **Selected Task** — `selectedTaskId` и `selectTaskAction` в `uiStore`: карточка и квадрант (entities) читают его сами, поэтому состояние в `shared`, а не в фиче. Переключение Matrix/List сбрасывает выделение. Undo (`performUndoable`) теперь выделяет и фокусирует восстановленную задачу. Если она не в матрице (Completed), панель сама снимает выделение.
- Карточка матрицы (`entities/matrixLayout/components/taskItem`) — `li role="option"` с `aria-selected` и `tabIndex={-1}`, внутри только текст и `DeadlineBadge` («in 3 days», «2 hours overdue», для screen reader «Deadline in …», абсолютная дата в `title`). Атрибуты `useSortable` не раздаются: роль `button` и описание клавиатурного drag больше не нужны. `ul` квадранта — `role="listbox"` с `aria-labelledby` на заголовок. Кольцо выделения: `ring-indigo-700` на белом offset в светлой теме, `ring-indigo-300` на `gray-950` в тёмной (обе пары больше 3:1). Красное кольцо просрочки убрано, просрочку показывает бейдж.
- Клик по пустому месту квадранта снимает выделение. Пустой квадрант по-прежнему открывает форму добавления, и при выделении тоже (так сказано в тикете; в прототипе первый клик только снимал выделение). Клики по кнопкам внутри квадранта (Expand/Collapse) выделение не трогают.
- Панель — `features/selectTask`: `TaskActionPanel` (логика) и приватный `ActionToolbar` (`role="toolbar"`, «Actions for “…”», группа «Move to» с именем, текущий квадрант `disabled`). Действия приходят пропсами из `widgets/taskMatrix` (`completeTask`, `deleteTask`, `moveTask` из `features/undo`), как в 07/09. Edit открывает `EditTaskDialog`, это общая обёртка `Modal` + `EditTaskForm`, её же использует List view.
- Выделение после действия. Complete и Delete ничего не двигают заранее: когда задача пропала из квадранта (в том числе из-за облака), панель в том же рендере показывает соседнюю (следующую, иначе предыдущую) и синхронизирует стор. Панель не размонтируется, фокус остаётся на нажатой кнопке. Move выделяет соседа до переноса, чтобы нажатая кнопка не стала `disabled`, а если задача осталась в исходном квадранте (сбой), выделение возвращается к ней. Если квадрант опустел, выделение снимается, и фокус пока падает с панели: правило «соседний квадрант / контейнер матрицы» — тикет 12.
- `Esc` снимает выделение (window-listener в `useClearSelectionOnEscape`), но не в текстовом поле и не при открытом `[aria-modal="true"]` или `dialog[open]`: второе — заранее под нативный `<dialog>` из тикета 13. Тикету 12 этот хук надо влить в общий обработчик клавиш матрицы.
- Toast над панелью: `useToastClearance(ref)` в `shared/ui/toast` меряет панель и ставит `--toast-bottom` на `<html>`, `ToastRegion` стоит на `bottom-[var(--toast-bottom,1rem)]`. Хук экспортируется из корня toast напрямую из файла с `'use client'`: barrel `./hooks` затягивал клиентские хуки в серверный `HomePage`, и `next dev` отдавал 500.
- Drag: библиотечные `MouseSensor` (`activationConstraint: { distance: 5 }`) и `TouchSensor` (300 мс, tolerance 10), `KeyboardSensor` удалён, `shared/lib/CustomSensors.ts` и все `data-no-dnd` удалены. `DragOverlay` рисует `TaskDragPreview` с `aria-hidden`, а не второй `option`.
- List view — `ListTaskItem` (`entities/matrixLayout/ui`): кнопки complete/edit/delete видны всегда, действия через Undo, текст с `Linkify`, дата создания осталась. С карточкой матрицы общий только `DeadlineBadge`. Прежний «Due: dd/MM/yyyy» в List view тоже заменён бейджем.
- Axe: исключения X2 (`nested-interactive`, `aria-allowed-role`, `list`) сняты, в `KNOWN_VIOLATIONS` остался только X1. `InsertTaskZone` — простые `div` внутри `listbox`, axe их не считает, их убирает срез G.
- Тесты: `src/app/tests/selectionPanel.test.tsx`, 21 шт. Выделение, снятие, одна задача, listbox/option, пустой квадрант, карточка без кнопок и ссылок, Move/Complete/Delete из панели с toast и переходом выделения (и фокусом на кнопке), Undo выделяет восстановленную, Edit, `Esc` в форме, List view, axe. Старые тесты переведены на панель (`undoToast`, `quadrantVocabulary`, `noErrorToast`). `TaskItem.test.tsx` удалён, его сценарий (правка не меняет квадрант) переехал на главный seam. Все 16 наборов jest зелёные (86 тестов), tsc и eslint чистые.
- В Chrome (desktop, тёмная тема, синтетические mouse-события): клик выделяет, дрожание в 2px остаётся кликом, сдвиг больше 5px переносит в другой квадрант с «Moved to Delegate», после drop выделение не переключается. Toast стоит на 8px выше панели. Touch и светлая тема в браузере не проверялись, в чек-листе раздел «F. Выделение и панель действий».

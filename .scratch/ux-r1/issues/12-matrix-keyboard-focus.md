# 12: Клавиатура матрицы и правила фокуса

**What to build:** Вся работа с матрицей доступна с клавиатуры. В матрицу попадают одной остановкой Tab, стрелками ходят по задачам, одной клавишей завершают, правят, переносят и удаляют. Фокус никогда не теряется. Срез F [спеки R1](../spec.md), решения: [Обнаружимость действий над задачей](../../ui-ux-audit/issues/05-task-actions-discoverability.md) (primary source — `prototype/task-actions`, вариант B), [Минимальная планка доступности](../../ui-ux-audit/issues/11-accessibility-baseline.md). Закрывает X3.

**Blocked by:** 11

**Status:** resolved

- [x] Матрица — одна остановка Tab, дальше roving tabindex. Фокус и выделение совпадают. Tab в матрицу выделяет последнюю выделенную задачу, а если её нет — первую в Do First (первую непустую, если Do First пуст).
- [x] **Переходное решение до среза G:** пустые квадранты в roving tabindex не участвуют. У полностью пустой матрицы нет остановки Tab.
- [x] Клавиши обрабатываются, только когда фокус не в поле ввода и не в открытом диалоге:

  | Клавиша | Без выделения | С выделением |
  |---|---|---|
  | ↓ / ↑ | ↓ выделяет первую задачу | следующая / предыдущая в квадранте, без зацикливания |
  | ← / → | — | соседний квадрант по сетке 2×2, та же позиция или последняя; пустые пропускаются |
  | `1–4` | открыть форму добавления в квадрант N | Move в квадрант N; в текущий — ничего |
  | `C` / Space | — | Complete |
  | `E` / Enter | — | Edit |
  | Del / Backspace | — | Delete |
  | `N` | добавить в Do First | добавить в квадрант выделения |
  | Esc | — | снять выделение |

- [x] **Переходное решение до среза G:** «добавить» по `N` и `1–4` открывает существующую форму добавления.
- [x] Глобальный обработчик `1–4` слит с обработчиком матрицы: клавиша срабатывает один раз.
- [x] На desktop у кнопок панели `kbd` показывает, что клавиша сделает сейчас: `1–4` — «Move to».
- [x] Tab с задачи переводит фокус в панель, Esc из панели возвращает на задачу.
- [x] Фокус после действия: следующая задача квадранта, иначе предыдущая, иначе ближайшая задача соседнего квадранта, иначе контейнер матрицы с `tabindex="-1"`. На `body` фокус не падает. После Undo фокус и выделение на восстановленной задаче.
- [x] Ядро навигации взято из прототипа (вариант B, сокращено):

## Comments

**Итог (ветка `ux-r1`).**
- **Tab stop.** `lastSelectedTaskId` в `uiStore` (`selectTaskAction` помнит последнюю непустую). `tabStopTaskId` (`entities/matrixLayout/lib`): выделенная → последняя выделенная → `firstTaskId` (первая в Do First, иначе первая непустая). `TaskItem` получает `isTabStop` и `tabIndex` 0/-1. Фокус с клавиатуры выделяет задачу (`onFocus`). Фокус от нажатия мышью выделение не трогает: флаг с `onPointerDown`, дальше решает клик, как в 11. У `li` есть `data-task-id`.
- **Клавиши.** `useMatrixKeys` (`features/selectTask/hooks`) — один window-listener вместо `shared/hooks/useKeyboardShortcuts` + `ClientShortcuts` (удалены) и `useClearSelectionOnEscape` (удалён). Клавиши не срабатывают в текстовом поле, в `select`, при открытом `[aria-modal]` / `dialog[open]`, с Ctrl/Cmd/Alt. Действия, кроме стрелок, не повторяются при удержании. `Enter`/`Space` на кнопке или ссылке остаются кнопке. Буквы определяются по `event.code`, если `key` не латинский, поэтому C/E/N работают и на кириллической раскладке. `Tab` с задачи уводит на первую кнопку панели, `Esc` из панели возвращает на задачу, `Esc` на задаче снимает выделение, фокус остаётся на задаче. ↓ без выделения выделяет задачу, на которой стоит фокус, иначе первую. Навигация — `arrowTargetId`, геометрия 2×2 — `gridNeighbours`. List view сохраняет только `1–4` → форма добавления, остальное придёт со срезом N. Поэтому `TaskActionPanel` смонтирован в `TaskMatrix` при обоих видах.
- **Фокус после действия.** `neighbourTaskId`: следующая → предыдущая → та же позиция (или последняя) ближайшего непустого квадранта: сначала в строке, потом в столбце, потом по диагонали. Фокус и выделение совпадают, поэтому соседняя задача получает и выделение. spec.md уточнена, там было «выделение снимается». `useFocusAfterAction` запоминает по `focusin`, был ли фокус в матрице. Если сфокусированный элемент исчез и фокус упал на `body`, он уходит на выделенную задачу или на контейнер матрицы. Контейнер — обёртка в `TaskMatrix`: `role="group"`, «Task matrix», `tabIndex=-1`, рамка по `focus-visible`. Move единственной задачи матрицы оставляет её выделенной в новом квадранте (и с клавиатуры, и из панели). Undo — как в 11 (`performUndoable`).
- **Подсказки.** Кнопки панели: `aria-keyshortcuts` и `kbd aria-hidden` (C, E, 1–4, Del), только при не-touch указателе. У текущего квадранта в Move to подсказки нет: его цифра ничего не делает.
- **Тесты.** `src/app/tests/matrixKeyboard.test.tsx`, 41 шт.: одна остановка Tab, возврат к последней выделенной, Tab → панель → Esc, пустая матрица, каждая строка таблицы, Enter на кнопке панели, клавиши в поле формы и с модификаторами, кириллица, List view, фокус после Complete/Delete/Move последней и единственной задачи, Undo после Complete/Delete/Move, подсказки и axe. Все 17 наборов jest зелёные (127 тестов), tsc и eslint чистые. В Chrome (desktop) проверены tab stop, ←/→, Delete последней задачи квадранта, Cmd+Z, Tab в панель, Esc назад и фокус на контейнере пустой матрицы.
- **Не сделано и оставлено следующим срезам.** На телефоне свёрнутые списки `hidden`: tab stop или цель стрелки может оказаться невидимой карточкой (срез H). Tab с задачи идёт сразу в панель, поэтому Expand/Collapse в квадранте достижимы только Shift+Tab из панели. Шпаргалка `?` и `<dialog>` с возвратом фокуса после правки — тикет 13. В чек-листе F добавлен проход только клавиатурой.

# 14: Индикатор «+N below» на всех ширинах

**What to build:** Если задачи не влезают в квадрант, внизу видно «+3 below ↓». Клик по индикатору прокручивает список. Задачи больше не обрезаются молча ни на телефоне, ни на desktop. Срез H [спеки R1](../spec.md), решение: [Мобильная матрица](../../ui-ux-audit/issues/06-mobile-matrix.md) (комментарий про все ширины), primary source — `CellList` в `prototype/task-actions`. Закрывает M2.

**Blocked by:** 13

**Status:** resolved

- [x] Со списков квадрантов убран `scrollbar-hidden`.
- [x] Внизу переполненного списка стоит индикатор «+N below ↓», где N — число задач, не видимых целиком ниже края. Индикатор пересчитывается при прокрутке и при изменении числа задач. Логика из прототипа (сокращено):

  ```ts
  const bottom = el.scrollTop + el.clientHeight;
  const hidden = items.filter((li) => li.offsetTop + li.offsetHeight > bottom + 2).length;
  ```

- [x] Клик по индикатору прокручивает список вниз, при `prefers-reduced-motion` без плавной анимации.
- [x] У индикатора доступное имя «N more tasks below», контраст текста не меньше 4.5:1.
- [x] Тест на главном seam: размеры задаются в тесте (jsdom не делает раскладку); проверяется число и исчезновение индикатора после прокрутки.

## Comments

**Итог (ветка `ux-r1`).**
- **`QuadrantTaskList`** (`entities/matrixLayout/components/quadrantTaskList`) — обёртка вокруг `ul role="listbox"` и индикатора. Индикатор стоит вне `listbox`, это не задача. `scrollbar-hidden` со списков убран, стили списка (`LIST_STYLES`) переехали из `matrixLayout/consts` в подкомпонент. Видимость на телефоне (`hidden sm:block` у свёрнутых) теперь на обёртке.
- **Подсчёт** — `tasksBelow` (`lib`), формула прототипа с допуском 2px, считаются только прямые дети-`option`, `InsertTaskZone` не в счёт. `offsetParent` задач — сам `ul` (`relative`). `useTasksBelowCount` пересчитывает после каждого рендера (добавление, удаление, правка), на `scroll` и через `ResizeObserver` (размер окна, Expand).
- **Клик** подводит первую невлезшую задачу к верху списка (`scrollTopBelow`). Если задача выше списка, прокрутка на страницу. В прототипе было `scrollBy(120)`. При `prefers-reduced-motion` прокрутка `auto`, иначе `smooth`.
- **Индикатор** «+N below ↓», имя «N more tasks below» («1 more task below» для одной). Тёмная плашка `gray-900`/белый текст, в тёмной теме `gray-100`/`gray-900`, контраст больше 15:1. Видимая высота 24px, `after:` расширяет цель до 44px. `tabIndex=-1`: матрица остаётся одной остановкой Tab, с клавиатуры список прокручивают стрелки (фокус сам прокручивает задачу в видимую область). `mousedown` не берёт фокус: иначе после клика, который докрутил до конца, кнопка исчезала бы с фокусом и он падал на `body`. Клик по индикатору не снимает выделение (обработчик квадранта пропускает кнопки).
- **Экранное имя не содержит видимый текст** («+3 below» и «3 more tasks below»). Так в спеке. Для голосового управления (2.5.3 Label in Name) это спорно, axe по умолчанию правило не проверяет.
- **Тесты.** `src/app/tests/listLayout.ts` — `mockListLayout({ listHeight, rowHeight })`: jsdom не делает раскладку, поэтому хелпер задаёт высоту `listbox` и строки `option`, `scrollTop`/`scrollTo` двигают список и шлют `scroll`. `src/app/tests/moreBelow.test.tsx`, 11 шт.: число, нет индикатора, когда всё влезает, по индикатору на квадрант и единственное число, пересчёт при прокрутке и исчезновение внизу, клик прокручивает, клик не снимает выделение, пересчёт после Delete, телефон (развёрнутый квадрант), фокус остаётся на задаче, нет `scrollbar-hidden`, axe. Все 19 наборов jest зелёные (155 тестов), tsc и eslint чистые.
- **Chrome** (desktop 1280×800 и телефон 390×844 с touch, тёмная тема): числа совпадают с видимым, клик докручивает до конца, полоса прокрутки видна, в развёрнутом квадранте индикатор стоит над полосой Collapse. Светлая тема, «Reduce motion», VoiceOver и реальный телефон не проверялись: в чек-листе раздел «H. Мобильная матрица и «+N below»».
- **Оставлено тикетам 15/16.** На телефоне свёрнутые списки по-прежнему `hidden`, индикатор виден только в развёрнутом квадранте. Задачу под полупрозрачной полосой Collapse (`pb-8`) подсчёт считает видимой. `MORE_BELOW_EXPANDED`, `LIST_EXPANDED` и пункт чек-листа про Collapse уходят вместе с Expand/Collapse.

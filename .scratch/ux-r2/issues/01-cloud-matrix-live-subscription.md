# 01: Облачная матрица по живой подписке

**What to build:** Облачная матрица вошедшего пользователя хранит кэш на устройстве (IndexedDB) и читается живой подпиской. Правки с другой вкладки или другого устройства появляются сами, молча. На устройстве, где пользователь уже работал, матрица открывается без лоадера, даже без сети. Ошибка загрузки больше не подменяет матрицу красным текстом. Заодно появляется тестовый seam вошедшего пользователя, на который опираются все следующие тикеты R2. Срез J1 [спеки R2](../spec.md) (разделы «Граница с облаком» и «J1»), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строки «Режим» и «Живое обновление».

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] Облачный клиент матрицы в `shared/api` — единственный модуль, который импортирует `firebase/firestore`. Интерфейс по смыслу как в спеке: `subscribe(uid, onSnapshot, onError)` со снимками `{ tasks, completedTasks, fromCache, hasPendingWrites }`, `write(uid, changes)`, `waitForPendingWrites()`, `clearDevice()`. Внутри `initializeFirestore` с `persistentLocalCache` + `persistentMultipleTabManager` и `onSnapshot` с `includeMetadataChanges: true` по `userId == uid`. Firestore создаётся лениво внутри клиента, `firebaseConfig` отдаёт только `app`. Схема документов не меняется.
- [x] Клиент аутентификации в `shared/api` — единственный модуль, который импортирует `firebase/auth` (подписка на пользователя, вход через Google, выход). `useAuth` работает поверх него. Вход через GitHub не трогаем.
- [x] Пока пользователь вошёл, приложение держит одну подписку. Каждый снимок заменяет облачные задачи и Completed в `tasksStore`. Разовый `syncTasks`/`getDocs` удалён. Смена пользователя переподписывает, выход отписывает. Подписка живёт на уровне приложения, а не матрицы.
- [x] Правка с другого устройства применяется без toast'а. Если Selected Task исчезла из матрицы, выделение снимается, фокус уходит на контейнер матрицы, на `body` он не падает.
- [x] Во время drag'а снимки к стору не применяются. Последний пришедший применяется после drop, предпросмотр не сбрасывается.
- [x] Лоадер показывается, пока нет первого снимка. Снимок из кэша с задачами показывается сразу. Снимок из кэша без задач держит лоадер до снимка с сервера, как сейчас. Ошибка подписки уходит в `console.error` и не подменяет матрицу.
- [x] Записи идут через `write` облачного клиента. В этом тикете допустимо писать всю матрицу, как сейчас. Запись только изменённого и отказ от `await` — тикет 02.
- [x] Тестовый seam: `renderHomePage` принимает `signedIn` и `cloud` (задачи на сервере, `deviceCache: 'warm' | 'empty'`, `network`). Вместо мока `firebaseConfig` как signed-out он подменяет оба клиента управляемым фейком облака. Фейк повторяет семантику из раздела Testing Decisions спеки: латентная компенсация, очередь при `offline`/`stalled`, подтверждение на следующем тике при `online`, `remoteChange`, `serverTasks()`, `reload()` с сохранением кэша и очереди. `goOffline`/`goOnline` переключают и `navigator.onLine` с событиями `online`/`offline`. Анонимные тесты R1 проходят без изменений.
- [x] Тесты на главном seam: вошедший видит задачи сервера; `remoteChange` появляется без toast'а; удалённая извне выделенная задача теряет выделение, фокус не на `body`; при `deviceCache: 'warm'` без сети матрица без лоадера; ошибка подписки не подменяет матрицу; axe чист у вошедшего.
- [x] В ручной чек-лист добавлен сценарий облака: две вкладки, правка в одной видна в другой; DevTools Offline и перезагрузка с тёплым кэшем; Firefox Private открывается без ошибок.

## Comments

- Облачный клиент: `src/shared/api/cloudMatrix` (`client.ts` — единственный импорт `firebase/firestore`, Firestore создаётся лениво, `clearDevice` обнуляет экземпляр для повторного создания). Чистый разбор «документ ↔ `Task`» в `lib` с табличным тестом. Клиент аутентификации — `src/shared/api/auth/client.ts`, `useAuth` поверх него, вход через GitHub перенесён в клиент без изменений поведения. `firebaseConfig` отдаёт только `app`.
- Подписка: `subscribeToCloudMatrix` в `tasksStore/actions/cloudSync.ts`, держит её `src/app/providers/CloudMatrixSync` в `AppShell` по `uid`. Флаг `isCloudLoaded` в сторе: `true` после снимка с сервера, снимка из кэша с задачами или ошибки подписки. Лоадер только при `activeState === 'firebase'`, чтобы Local-матрица вошедшего не висела на лоадере (замечание ревью). Возможен один кадр Local-матрицы до переключения `SwitchTaskSource` на облако после входа — проверить в ручном сценарии.
- Выделение снимается, если снимок убрал задачу, которая ещё была в сторе: свои Complete/Delete/Move убирают её из стора раньше снимка, поэтому для них работает правило соседа из R1.
- Drag: снимки держатся с `dragStart`; на drop удержанный снимок применяется до записи, перестановка внутри квадранта считается по свежему стору. Иначе запись всей матрицы из устаревшего стора затирала удалённые правки (переименование, удаление), пришедшие во время drag.
- «Clear all» удаляет по id из снимка (без `getDocs` — его нельзя было оставить, раз SDK импортирует только клиент), но пока ждёт сервер, как и остальные действия. Отказ от `await` и запись только изменённого — тикет 02.
- Фейк облака: `src/app/tests/fakeCloud.ts`, `renderHomePage({ signedIn, cloud })` возвращает `cloud` (`goOffline`/`goOnline`/`stall`/`remoteChange`/`failSubscription`/`serverTasks`) и `reload()`. `rejectNextWrite` и `expireSession` не добавлены — их добавят тикеты 06 и 07. Фейк не различает пользователей (один сервер на всех `uid`), поэтому переподписку при смене пользователя тест не проверяет; понадобится в 03.
- Хелперы drag мышью вынесены из `dragOverRing.test.tsx` в `src/app/tests/drag.ts`, поведение теста не изменилось.
- Ручной чек-лист: раздел «J. Облачная матрица вошедшего пользователя», сценарии 1–6. Настоящий Firestore (две вкладки, офлайн с перезагрузкой, Firefox Private) в этой сессии не проверялся.

# 02: Действия не ждут облака и пишут только изменённое

**What to build:** Вошедший пользователь без сети добавляет, меняет, переносит, завершает, восстанавливает и удаляет задачи так же, как при сети. Форма добавления закрывается сразу, повторный Enter не создаёт дубль. Правки переживают перезагрузку и сами уходят в облако, когда сеть вернётся. Правка на одном устройстве не затирает чужие задачи. Срез J1 [спеки R2](../spec.md), замечания для реализации из [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md).

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] Действия стора, как и сейчас, меняют стор сразу, затем вызывают `write` облачного клиента без `await`. Сигнатуры действий и revert'ы для Undo не меняются, `performUndoable` как есть: toast появляется без задержки сети.
- [ ] Каждое действие пишет одним батчем задачу, которую меняет, и `order` задач в затронутых квадрантах или в Completed. Удаление — `delete` по id. Полная перезапись матрицы (`syncTasksToFirebase` всех задач) удалена. Конфликт порядка — «последняя запись выигрывает».
- [ ] Выбор «действие → `TaskChange[]`» и разбор «документ Firestore ↔ `Task`» — чистые функции с табличными тестами (тонкий seam из спеки).
- [ ] «Clear all» в Completed удаляет батчем по id из текущего снимка, повторного `getDocs` нет. `window.confirm` у «Delete all» остаётся до среза O.
- [ ] «Copy all tasks to Cloud» пишет через облачный клиент и не ждёт сервер: без сети переключает на облако сразу. Сама кнопка остаётся до среза K.
- [ ] Минимальная модель синхронизации: она регистрирует промис каждой записи и знает, есть ли Pending changes и сколько записей этой сессии не подтверждено. UI у неё пока нет, её используют тикеты 04, 06, 08, 09. Реакции на отказ здесь нет: отказ уходит в `console.error` (тикет 06).
- [ ] Тесты на главном seam, сеть `offline`: добавить (форма закрыта после первого Enter, дубля нет), изменить, Move, Complete, Restore, Delete, Undo — всё видно сразу; `reload()` — правки на месте; `goOnline` — они в `serverTasks()`; Move не трогает задачу, изменённую через `remoteChange` в другом квадранте; «Clear all» без сети после `goOnline` — completed на сервере пусты.
- [ ] Чек-лист: правки без сети, перезагрузка без сети, возврат сети — правки видны во второй вкладке или в консоли Firebase.

# 03: Выход из аккаунта стирает кэш на устройстве

**What to build:** После выхода из аккаунта задачи вошедшего пользователя не остаются на устройстве: кэш облачной матрицы в IndexedDB стирается всегда, без вопроса «доверяете ли устройству». Без этого тикета кэш из 01 оставил бы задачи на диске общего компьютера, поэтому J1 уходит в `main` только вместе с ним. Срез J1 [спеки R2](../spec.md), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строка «Выход из аккаунта» (без диалога — он в тикете 09).

**Blocked by:** 01

**Status:** resolved

- [x] «Sign out» отписывает от облака и вызывает `clearDevice` облачного клиента: `terminate` + `clearIndexedDbPersistence`.
- [x] После очистки следующий вход работает без перезагрузки: клиент создаёт Firestore заново. Если `firebase@11.4.0` не даёт снова вызвать `initializeFirestore` на том же `app`, страница после выхода перезагружается. Какой вариант выбран, записать в Comments.
- [x] Если очистка не удалась (другая вкладка держит IndexedDB, `failed-precondition`), ошибка уходит в лог, и очистка повторяется при следующем запуске без вошедшего пользователя. Выход в одной вкладке доходит до всех через подписку на пользователя, и каждая отпускает IndexedDB.
- [x] Кэш стирается только при выходе по «Sign out». Потерю сессии без «Sign out» обрабатывает тикет 07, и там кэш не стирается.
- [x] Тесты на главном seam: после «Sign out» фейк отчитывается о стёртом кэше и очереди; `reload()` без входа ничего облачного не показывает; повторный вход снова показывает задачи сервера.
- [x] Чек-лист: после выхода в DevTools → Application нет базы Firestore; выход при двух открытых вкладках.

## Comments

- Повторный вход без перезагрузки: `firebase@11.4.0` `terminate` вызывает `_removeServiceInstance`, поэтому `initializeFirestore` на том же `app` снова работает. Клиент создаёт Firestore заново (`getDb` после `clearDevice`), страница не перезагружается.
- Протокол в `src/shared/api/cloudMatrix/device.ts`: «Logout» (`features/auth`) ставит запрос очистки в localStorage (`eisenhower-clear-cloud-device`, запасной флаг в памяти вкладки) и выходит. `CloudMatrixSync` в любой вкладке, увидев «пользователя нет» (не во время загрузки auth), после отписки вызывает `clearDeviceIfRequested` → `clearDevice`. Успех снимает запрос, неудача уходит в `console.error`, и запрос ждёт следующего запуска без входа. Потеря сессии запроса не ставит, поэтому кэш не стирается (тикет 07). `clearDevice` убран из public API `cloudMatrix`, снаружи только запрос и очистка по запросу.
- Вход снимает запрос (`cancelDeviceClear`), и неудачный `signOut` тоже. Иначе после неудачной очистки и повторного входа потеря сессии стёрла бы очередь неотправленных правок вошедшего (замечание ревью, есть тест). Если на устройстве остался кэш прошлого пользователя, его стирает следующий «Logout».
- Известные ограничения: вход в те же миллисекунды, пока идёт очистка, открывает новый экземпляр, и `clearIndexedDbPersistence` падает с `failed-precondition`: это только лог. При двух вкладках одна «Clearing … failed» в консоли ожидаема, базу стирает вторая. Что происходит после `terminate` с промисами неподтверждённых записей из 02, в jest не проверяется. Это касается J3/J4: реакция на отказ не должна показывать ошибку уже вышедшему.
- Фейк: `cloud.deviceTasks()` (кэш и очередь на устройстве), `holdDeviceInAnotherTab`/`closeAnotherTab` (очистка падает с `failed-precondition`) и минимальный `expireSession` (auth → null без Sign out). Тикет 07 дополнит его поведением при очереди. Тесты: `src/app/tests/signOut.test.tsx`.
- Ручной чек-лист: раздел J, «Выход стирает кэш на устройстве». С настоящим Firestore в этой сессии не проверялся.

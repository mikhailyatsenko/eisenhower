# 05: Холодный старт без сети

**What to build:** Вошедший пользователь, впервые открывший приложение на этом устройстве без сети, видит матрицу с полосой офлайна и строкой «Your tasks are in your account. They'll appear when you're back online.», а не пустую матрицу или долгий лоадер. Добавлять задачи можно. Когда сеть вернётся, задачи из облака появятся сами, а строка исчезнет. Срез J2 [спеки R2](../spec.md), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строка «Холодный старт без кэша».

**Blocked by:** 04

**Status:** resolved

- [x] Первый снимок из кэша (`fromCache`) пустой и есть признак офлайна (`navigator.onLine === false` или 10 с без ответа сервера) — лоадер снимается, показываются матрица, полоса offline и строка над матрицей.
- [x] Первый пустой снимок из кэша при сети держит лоадер до снимка с сервера. После 10 с без ответа срабатывает правило выше.
- [x] Строка исчезает с первым снимком с сервера. Задачи, добавленные до этого, остаются и уходят в облако вместе с задачами сервера.
- [x] Молча пустая матрица вошедшему больше не показывается.
- [x] Тесты на главном seam: `deviceCache: 'empty'` + `offline` — матрица, полоса и строка; задачу можно добавить; `goOnline` — строки нет, видны задачи сервера и добавленная; `deviceCache: 'empty'` + `stalled` — лоадер, через 10 с строка; axe чист.
- [x] Чек-лист: чистый профиль браузера, вход, DevTools Offline, перезагрузка.

## Comments

- Сигнал `isAwaitingServer` в `syncStore`: вошедший, в кэше не было облачной матрицы, сервер ещё не ответил. Ставится при подписке, снимается первым снимком с сервера, снимком кэша с задачами (тёплый кэш) или ошибкой подписки. Часы lie-fi теперь идут и при нём, поэтому `isStalled` значит «сервер молчит 10 с при сети», когда ждут Pending changes или пустой кэш. Правило «10 с без ответа сервера» отсчитывается от подписки, а не от первого пустого снимка: при `stalled` снимка может не быть совсем (фейк так и делает). Правило 04 не меняется: тёплый кэш, `stalled`, правок нет — полосы нет (есть тест).
- Решение «показать матрицу без сервера» принимает `showWithoutServer` в `tasksStore/actions/cloudSync.ts`, подписанный на `syncStore`: пустой снимок из кэша + нет сети, или 10 с без ответа. После этого матрица не прячется обратно за лоадер, даже если сеть вернулась, а сервер ещё молчит. Задачи, добавленные до ответа, строку не снимают: после пустого кэша снимки из кэша с задачами считаются своими правками.
- Строка — `<p>` в `TaskMatrix` над матрицей, только при `activeState === 'firebase'`. Не live-регион: об офлайне объявляет полоса.
- Ревью: фаза загрузки облака описана тремя флагами (`isCloudLoaded`, `isAwaitingServer`, модульный `isCacheEmpty`) — кандидат на один тип фазы, оставлено, пока J3 не добавит свои состояния. Хелперы тестов (`addTask`, `advance`, `syncBar`, `tasksIn`) скопированы из `syncBar.test.tsx` и `cloudMatrix.test.tsx`, как принято в `src/app/tests`. Известные мелочи: во время drag удержанный снимок сервера держит строку до drop; вошедший на Local-матрице при пустом кэше и молчащем сервере через 10 с видит полосу offline (сервер правда недоступен).
- Пустая облачная матрица нового пользователя в кэше неотличима от холодного старта: без сети он увидит строку «Your tasks are in your account…». Следует из решения «Отличаем по `fromCache` первого снимка».
- Ручной чек-лист: раздел J, «Холодный старт без сети». Настоящий Firestore в этой сессии не проверялся.

# 06: Красная полоса при отказе облака

**What to build:** Если облако отказалось принять правки (нет доступа, квота), вошедший пользователь видит красную полосу «Some changes couldn't be saved to your account.» с кнопкой «Reload». Отказанная правка откатывается на экране. «Reload» заново подтягивает матрицу с сервера. Отсутствие сети красной полосой не бывает никогда. Срез J3 [спеки R2](../spec.md), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строка «Ошибка синхронизации»; Sync error в CONTEXT.md.

**Blocked by:** 04

**Status:** resolved

- [x] Sync error — запись отклонена постоянной ошибкой (`permission-denied`, квота, `invalid-argument` и т. п.) или подписка упала с ошибкой. `unavailable` и отсутствие сети — никогда не Sync error.
- [x] Отказанная правка исчезает с экрана: стор следует снимку, в котором SDK уже откатил мутацию. Перечня откаченных правок нет. Undo-toast отказанного действия не трогаем.
- [x] Модель синхронизации получает состояние `error` с действием `reload`. Красная полоса стоит на месте нейтральной, `role="alert"`, объявляется один раз, фокус не перехватывает. «Reload» доступен по Tab. Отличие от нейтральной полосы несут текст и кнопка, а не только цвет. Контраст ≥ 4.5:1 в обеих темах.
- [x] «Reload» пересоздаёт подписку, полоса исчезает с первым снимком с сервера. Страница не перезагружается, выделение и открытые диалоги не сбрасываются. Сама полоса ошибки не исчезает.
- [x] Тесты на главном seam: `rejectNextWrite('permission-denied')` после правки — `alert` с текстом и «Reload», правка откатилась; «Reload» убирает полосу; `goOffline` и `stall` никогда не дают `alert`; axe чист.
- [x] Чек-лист: отказ через временное правило в тестовом проекте Firebase или эмуляторе, VoiceOver объявляет alert.

## Comments

- Модель: в `SyncState` сигнал `syncError: SyncErrorCause | null` хранит причину (`'refused'`), а `nextSyncBar` переводит её в полосу `{ kind: 'error', action: 'reload' }`. Тикет 07 добавит причину потери сессии и действие `signIn` в ту же таблицу. Ошибка важнее сети. Когда её снимают, полоса начинается заново: без «Syncing…» и «All changes saved», которые бывают только после offline.
- `trackCloudWriteAction` превращает отклонение записи с `isRejected` в Sync error (`failSyncAction`). Прочие отклонения только логируются. Ошибка подписки — всегда Sync error: слушатель после неё мёртв, поэтому `console.error` из подписки убран.
- Квоту в `REJECTED_CODES` не добавляли. SDK считает `resource-exhausted` временной ошибкой и повторяет запись, до промиса `write` она не доходит. Упёршийся в квоту пользователь увидит offline через lie-fi, а не красную полосу. Вне того, что может сделать клиент.
- «Reload» — `reloadCloudMatrixAction` в `tasksStore/actions/cloudSync.ts`: снимает текущий слушатель и подписывается заново. Матрица остаётся на экране, флаги фазы загрузки не сбрасываются. Ошибку снимает первый снимок новой подписки с `fromCache: false`. Если сети нет, полоса ждёт её возвращения.
- Полоса — `widgets/syncBar`: `role="alert"` монтируется рядом со status-регионом «Sync status» внутри той же sticky-обёртки. Status в это время пуст. Когда полоса с кнопкой уходит, а фокус был в ней, фокус переходит на выделенную задачу, а без неё — на обёртку полосы (`tabIndex={-1}`). Так он не падает на `body`, и следующий Tab идёт дальше с того же места.
- Фейк: `cloud.rejectNextWrite(code)`. Отклонённая запись не доходит до сервера и уходит из локального вида. Её промис отклоняется с `{ code, isRejected: true }`. Для `waitForPendingWrites` она считается отвеченной.
- Тесты: `src/app/tests/syncError.test.tsx`. axe проверяется в отдельном describe на реальных таймерах.
- Ревью, оставлено как есть: если подписка упала, а потом отклонили запись, до «Reload» отката на экране нет (слушатель мёртв, полоса уже стоит). При нескольких вкладках первый снимок новой подписки может прийти с `fromCache: false` из общего view раньше, чем ответит сервер. Хелперы тестов скопированы, как принято в `src/app/tests`.
- Ручной чек-лист: раздел J, «Красная полоса при отказе облака». Настоящий Firestore, эмулятор, контраст в браузере и VoiceOver в этой сессии не проверялись.

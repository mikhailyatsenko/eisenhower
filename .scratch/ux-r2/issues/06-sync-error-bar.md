# 06: Красная полоса при отказе облака

**What to build:** Если облако отказалось принять правки (нет доступа, квота), вошедший пользователь видит красную полосу «Some changes couldn't be saved to your account.» с кнопкой «Reload». Отказанная правка откатывается на экране. «Reload» заново подтягивает матрицу с сервера. Отсутствие сети красной полосой не бывает никогда. Срез J3 [спеки R2](../spec.md), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строка «Ошибка синхронизации»; Sync error в CONTEXT.md.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] Sync error — запись отклонена постоянной ошибкой (`permission-denied`, квота, `invalid-argument` и т. п.) или подписка упала с ошибкой. `unavailable` и отсутствие сети — никогда не Sync error.
- [ ] Отказанная правка исчезает с экрана: стор следует снимку, в котором SDK уже откатил мутацию. Перечня откаченных правок нет. Undo-toast отказанного действия не трогаем.
- [ ] Модель синхронизации получает состояние `error` с действием `reload`. Красная полоса стоит на месте нейтральной, `role="alert"`, объявляется один раз, фокус не перехватывает. «Reload» доступен по Tab. Отличие от нейтральной полосы несут текст и кнопка, а не только цвет. Контраст ≥ 4.5:1 в обеих темах.
- [ ] «Reload» пересоздаёт подписку, полоса исчезает с первым снимком с сервера. Страница не перезагружается, выделение и открытые диалоги не сбрасываются. Сама полоса ошибки не исчезает.
- [ ] Тесты на главном seam: `rejectNextWrite('permission-denied')` после правки — `alert` с текстом и «Reload», правка откатилась; «Reload» убирает полосу; `goOffline` и `stall` никогда не дают `alert`; axe чист.
- [ ] Чек-лист: отказ через временное правило в тестовом проекте Firebase или эмуляторе, VoiceOver объявляет alert.

# 07: Сессия закончилась при неотправленных правках

**What to build:** Если сессия вошедшего пользователя закончилась сама (он не нажимал «Sign out»), а у него есть Pending changes, красная полоса предлагает «Sign in again». После повторного входа в тот же аккаунт правки уходят в облако: кэш и очередь на устройстве в этом случае не стираются. Срез J3 [спеки R2](../spec.md), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строка «Ошибка синхронизации».

**Blocked by:** 03, 06

**Status:** resolved

- [x] Клиент аутентификации сообщил «пользователя нет» без «Sign out», и в этот момент есть Pending changes → состояние `error` с действием `signIn`: красная полоса с тем же текстом, что в 06, и кнопкой «Sign in again», которая запускает вход через Google.
- [x] В этом случае `clearDevice` не вызывается. После входа в тот же аккаунт очередь уходит, полоса исчезает.
- [x] Без Pending changes потеря сессии ведёт себя как сейчас, полосы ошибки нет.
- [x] Тесты на главном seam: `goOffline`, правка, `expireSession` — `alert` с «Sign in again»; вход тем же uid и `goOnline` — правка в `serverTasks()`, полосы нет; `expireSession` без очереди — `alert` нет; axe чист.

## Comments

- Модель: причина `sessionExpired` в `SyncErrorCause` → действие `signIn` в той же таблице `nextSyncBar`. Ошибка проверяется раньше `isSignedIn`: истёкшая сессия показывает полосу, когда никто не вошёл. `'refused'` сюда не протекает, потому что отписка (`resetSyncAction`) снимает любую ошибку. Ошибку снимает `startSyncAction`, то есть новая подписка после входа. Если сети нет, после входа видна полоса offline.
- Отличить потерю сессии от «Sign out» помогает запрос очистки из 03. Sign out ставит запрос, вход его снимает (`isDeviceClearRequested` теперь в public API `cloudMatrix`). В `CloudMatrixSync` cleanup подписки запоминает, были ли Pending changes, до того как отписка сбросит модель. Эффект «пользователя нет» дальше решает так: есть запрос — стереть устройство, запроса нет, а правки были — `failExpiredSessionAction`. Кэш не стирается, потому что запроса нет. Так было и до 07.
- «Sign in again» в `SyncBar` вызывает `handleGoogleSignIn` из `useAuth`. Если попап закрыт, ошибка только логируется и полоса остаётся. Когда полоса уходит, фокус ведёт себя как в 06.
- Фейк не менялся. `expireSession` не трогает очередь, а `signInWithGoogle` возвращает последнего пользователя, этого хватает для сценария.
- Тесты: `src/app/tests/syncError.test.tsx`, describe «Sync error when the session ends by itself» и axe в describe на реальных таймерах. В CONTEXT.md к Sync error дописано, что при истёкшей сессии правки не отказаны, а ждут на устройстве.
- Ревью, известные ограничения:
  - Pending changes замеряются в cleanup, после коммита React. Настоящий Firestore при смене пользователя сам переключает локальный вид на очередь нового (анонимного) пользователя. Он может успеть прислать снимок с `hasPendingWrites: false`. Записи этой сессии всё равно учтены: их промисы висят в `unconfirmedWrites`. Но очередь, оставшаяся от прошлой сессии (перезагрузка без сети, потом истекла сессия), может остаться незамеченной, и полосы не будет. Jest это не проверяет, фейк так не умеет.
  - Потерю сессии страница замечает только открытой. Если перезагрузить страницу после того, как сессия истекла, полосы нет, хотя очередь в IndexedDB лежит.
  - Полосу снимает вход в любой аккаунт. Очередь прежнего пользователя тогда молча остаётся на устройстве, и следующий «Sign out» её сотрёт. Спека этот случай не рассматривает.
- Ручной чек-лист: раздел J, «Сессия закончилась при неотправленных правках». С настоящим Firebase и VoiceOver в этой сессии не проверялся.

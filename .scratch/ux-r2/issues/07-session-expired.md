# 07: Сессия закончилась при неотправленных правках

**What to build:** Если сессия вошедшего пользователя закончилась сама (он не нажимал «Sign out»), а у него есть Pending changes, красная полоса предлагает «Sign in again». После повторного входа в тот же аккаунт правки уходят в облако: кэш и очередь на устройстве в этом случае не стираются. Срез J3 [спеки R2](../spec.md), решение: [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md), строка «Ошибка синхронизации».

**Blocked by:** 03, 06

**Status:** ready-for-agent

- [ ] Клиент аутентификации сообщил «пользователя нет» без «Sign out», и в этот момент есть Pending changes → состояние `error` с действием `signIn`: красная полоса с тем же текстом, что в 06, и кнопкой «Sign in again», которая запускает вход через Google.
- [ ] В этом случае `clearDevice` не вызывается. После входа в тот же аккаунт очередь уходит, полоса исчезает.
- [ ] Без Pending changes потеря сессии ведёт себя как сейчас, полосы ошибки нет.
- [ ] Тесты на главном seam: `goOffline`, правка, `expireSession` — `alert` с «Sign in again»; вход тем же uid и `goOnline` — правка в `serverTasks()`, полосы нет; `expireSession` без очереди — `alert` нет; axe чист.

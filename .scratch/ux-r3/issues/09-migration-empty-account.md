# 09: Migration в пустой аккаунт

**What to build:** Анонимный пользователь с задачами входит в пустой аккаунт, и задачи сами переезжают в облако: матрица не меняется, toast «N tasks moved to your account» висит, пока пользователь не начнёт работать. Задачи устройства стираются только после подтверждения сервером, поэтому плохая сеть, закрытая вкладка или отказ облака не теряют и не задваивают их. Undo добавит тикет 10. Срез K [спеки R3](../spec.md), решения: [Модель «одна матрица»](../../ui-ux-audit/issues/03-one-matrix-model.md), [Офлайн для вошедшего пользователя](../../ui-ux-audit/issues/17-offline-ux.md) (строка «Migration»), [Поведение toast-уведомлений](../../ui-ux-audit/issues/12-toast-behaviour.md).

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] Migration нужна, когда пользователь вошёл, на устройстве есть задачи, которых нет в облаке (по id), и для этого `uid` не записан отказ (отказ появится в 10). Правило одно для входа кнопкой, входа в другой вкладке и пользователей, вошедших до R3.
- [ ] Решение принимается, когда облако известно (снимок с сервера или из кэша устройства с задачами — то же условие, что снимает лоадер в R2). Облако «пусто», если в нём нет задач, кроме задач с этого устройства.
- [ ] Чистая функция плана: задачи устройства (активные и Completed) + снимок облака → решение `none` | `move` | `ask`, N, `TaskChange[]`. Те же id, текст, `createdAt`, дедлайн, `completedAt`; порядок квадрантов сохраняется; задача с id, уже лежащим в облаке, не пишется. `ask` обрабатывает тикет 11, до него ничего не происходит.
- [ ] `move`: одна запись через облачный клиент, задачи сразу видны в матрице из подписки; сразу toast «N tasks moved to your account» («1 task moved to your account»), N — все перенесённые, активные и Completed.
- [ ] Toast Migration не гаснет через 6 с: висит до первого изменения матрицы (добавить, изменить, Complete, Delete, Move, Restore), смахивания или замены следующим toast. Выделение изменением не считается.
- [ ] После `waitForPendingWrites` с устройства удаляются только задачи, которые есть в облаке по снимку с сервера. Все задачи устройства уже в облаке (вкладку закрыли до очистки) → очистка без toast.
- [ ] Отказ облака — Sync error из R2; задачи остаются на устройстве.
- [ ] Тесты. Seam 2 — таблица плана: облако пусто, облако с задачами, все уже в облаке, часть уже в облаке, только Completed, те же id. Главный seam (вход посреди теста — расширение `renderHomePage` и фейка): анонимный с 3 задачами входит в пустой аккаунт → те же задачи в матрице, `status` «3 tasks moved to your account», через 6+ с (fake timers) toast на месте, после Complete — исчез; в `serverTasks()` те же тексты; после Sign out матрица пуста; `stall` сразу после входа → toast есть, `reload()` до `goOnline` — ни дубля, ни вопроса, после `goOnline` на сервере по одной копии; `rejectNextWrite` на переносе → `alert`, после Sign out задачи устройства на месте; старт вошедшим с задачами на устройстве и пустым облаком → тот же перенос.
- [ ] Чек-лист, раздел K: настоящий вход через Google с задачами на устройстве в пустой аккаунт; DevTools → Offline сразу после входа, перезагрузка, возврат сети — в консоли Firebase те же id, дублей нет; VoiceOver объявляет toast.

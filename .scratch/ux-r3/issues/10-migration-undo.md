# 10: Undo Migration

**What to build:** Пользователь, который не хотел переносить задачи, отменяет Migration кнопкой Undo в toast или `Ctrl/Cmd+Z`: аккаунт и устройство возвращаются как до входа, и приложение больше не предлагает перенос, пока он вошёл. Срез K [спеки R3](../spec.md) (дополнение спеки), решения: [Модель «одна матрица»](../../ui-ux-audit/issues/03-one-matrix-model.md), [Поведение toast-уведомлений](../../ui-ux-audit/issues/12-toast-behaviour.md).

**Blocked by:** 09

**Status:** resolved

- [x] Toast Migration получает Undo; `Ctrl/Cmd+Z` отменяет Migration, пока toast виден.
- [x] Undo удаляет перенесённые задачи из облака, возвращает их на устройство, если их уже очистили, и записывает на устройстве отказ для этого `uid`.
- [x] С отказом правило Migration не срабатывает: перезагрузки перенос не повторяют. Отказ стирается при выходе, при следующем входе правило работает снова.
- [x] Undo — ещё одна запись, без сети работает так же (R2). После Undo toast не показывается.
- [x] Тесты на главном seam: Undo → облако как до входа (`serverTasks()`), `reload()` без переноса и toast; после Sign out задачи устройства на месте; повторный вход → перенос снова; `Ctrl+Z` при видимом toast делает то же; Undo без сети, затем `goOnline` — на сервере задач устройства нет.
- [x] Чек-лист, раздел K: Undo после настоящего входа, в консоли Firebase задач устройства нет, после выхода они в матрице.

## Comments

**Что сделано.**

- **Undo в toast Migration.** У toast «N tasks moved to your account» теперь есть действие Undo с `shortcutKey: 'z'`, поэтому `Ctrl/Cmd+Z` работает, пока toast виден, как у обычного Undo. Toast по-прежнему `isPersistent` и гаснет при первом изменении матрицы. После Undo нового toast нет.
- **Что делает Undo** (`startMigration`):
  - останавливает Migration: очистка устройства, если она ещё ждёт сервер, не выполнится;
  - записывает отказ для `uid`;
  - возвращает матрицу устройства, какой она была при решении (`restoreDeviceAction`): если очистка уже прошла, задачи вернутся, если нет — ничего не изменится;
  - одной записью удаляет из облака все задачи устройства (`removeFromCloudAction`), в том числе те, что оставил там оборванный перенос. Иначе после Undo они остались бы и в аккаунте, и на устройстве. Запись учитывает sync model: без сети она ждёт в очереди после записи переноса, а отказ сервера показывает Sync error.
- **Отказ** (`features/migration/model/refusal`) лежит в отдельном ключе localStorage `eisenhower-migration-refused` со значением `uid`, а не в persist-сторе. Так его видят все вкладки, и persist другой вкладки не может записать его обратно. С отказом `startMigration` ничего не решает и не чистит, поэтому перезагрузки перенос не повторяют.
- **Стирание отказа.** Оно происходит при выходе: `Migration` при уходе пользователя вызывает `forgetMigrationRefusalOnSignOut`. Отказ стирается, только если есть запрос на очистку устройства (`isDeviceClearRequested`). Этот запрос ставит Sign out в этой или другой вкладке, а истёкшая сессия его не ставит и отказ оставляет. Без localStorage отказ не хранится, но тогда и задачи устройства не переживают визит.
- **cloudSync.** `moveToCloudAction` и новый `removeFromCloudAction` пишут через общий `writeForMigration`: одна запись, которая не считается изменением матрицы пользователя.

**Тесты** (`src/app/tests/migration.test.tsx`, блок «Undo Migration»):

- Undo → на сервере пусто, матрица пуста, toast нет. К клику очистка устройства на онлайн-фейке уже прошла (проверено временным логом), так что тест проверяет и возврат очищенных задач. `reload()` без переноса и toast. После Sign out задачи устройства на месте. Повторный вход снова переносит их с тем же toast.
- `Ctrl+Z` при видимом toast делает то же самое.
- Undo после `goOffline`, затем `goOnline` → на сервере задач устройства нет, после выхода они на устройстве.
- Оборванный перенос: одна задача устройства уже в облаке, после Undo её нет ни в матрице, ни на сервере.
- Все 44 набора и 363 теста зелёные.

Чек-лист: блок «Undo Migration» в разделе K. В блоке 09 строка VoiceOver теперь с «Undo with ⌘Z».

**Проверено в Chrome** (dev-сервер на 3100, изолированный контекст):

- desktop 1280px: анонимная матрица, добавление, Complete, toast «Task completed» с `⌘Z` и отмена по `Meta+Z`, фокус на восстановленной задаче, в консоли чисто;
- эмуляция 375×667 с touch: сетка, «Tap to add», «Tap a task to select it».

**Известные ограничения.**

- Настоящего входа через Google в сессии нет. Toast Migration с Undo в браузере не видел, это покрывают jest и чек-лист K.
- Фокус после клика по Undo уходит на `body`: кнопка исчезает вместе с toast, а восстановленной задачи, на которую его можно перевести, в матрице вошедшего нет. При `Ctrl/Cmd+Z` фокус остаётся на месте. Если нужно, стоит решить, куда его ставить (например, на группу «Task matrix», как в J1).
- Две вкладки: Undo в одной, пока другая ещё чистит устройство по своему снимку, упирается в то же ограничение persist `tasksStore` без синхронизации между вкладками, что описано в тикете 09.

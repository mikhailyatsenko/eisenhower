# R3 «Всё понятно без объяснений»

Status: ready-for-agent

Третий релиз по [спеке UX-изменений](../ui-ux-audit/spec.md). В него входят пять срезов, у каждого свой PR `ux-r3` → `main`:

- **G «Добавление кликом по пустому месту»**;
- **Q «Снятие выделения»** (дополнение спеки, добавлен после G);
- **I «Подсказки внутри матрицы»**;
- **K «Одна матрица и Migration»**;
- **L «Шапка и навигация»**.

Решения приняты в тикетах аудита и здесь не пересматриваются:

- [Обнаружимость действий над задачей](../ui-ux-audit/issues/05-task-actions-discoverability.md) — G;
- [Онбординг первого визита](../ui-ux-audit/issues/08-first-visit-onboarding.md) — I;
- [Модель «одна матрица»](../ui-ux-audit/issues/03-one-matrix-model.md) и дополнение из [Офлайн для вошедшего пользователя](../ui-ux-audit/issues/17-offline-ux.md) (строка «Migration») — K;
- [Шапка и навигация](../ui-ux-audit/issues/07-header-navigation.md) — L;
- [Поведение toast-уведомлений](../ui-ux-audit/issues/12-toast-behaviour.md) — toast Migration;
- [Минимальная планка доступности](../ui-ux-audit/issues/11-accessibility-baseline.md) — общая планка для всех срезов.

Спека собирает эти решения в один документ для реализации и добавляет то, чего в тикетах нет:

- что делает клик по пустому месту при выделенной задаче;
- куда уходит фокус из инлайн-поля;
- как инлайн-поле ведёт себя на телефоне;
- как снять выделение кликом вне квадранта и кнопкой в панели;
- когда Migration запускается и когда повторяется;
- что делают «Don't add» и Undo Migration;
- когда видна подсказка после выхода;
- где шапка живёт на других страницах;
- тестовый seam и разбивку на срезы.

Такие дополнения помечены словами «(дополнение спеки)».

Термины взяты из [CONTEXT.md](../../CONTEXT.md): **Matrix**, **Storage**, **Migration**, **Pending changes**, **Sync error**, **Selected Task**, **Quadrant**, **List view**. Ветки и мерж — по правилам `CLAUDE.md`: тикеты коммитятся в `ux-r3`, PR в `main` открывается после последнего тикета среза.

## Problem Statement

Новичок справляется с основными сценариями (R1), вошедший пользователь не теряет правки (R2). Но приложение всё ещё требует объяснений, которых нигде нет.

- **Добавить задачу в нужный квадрант неочевидно.** Клик по пустому месту работает только в полностью пустом квадранте, и то открывает большую модальную форму. В непустом квадранте клик ничего не добавляет, а вставка между задачами — полоска высотой в пару пикселей (M4). Несколько задач подряд нельзя ввести, не открывая форму заново.
- **Пустая матрица ничего не подсказывает.** Пустой квадрант не говорит, что туда класть и что по нему можно кликнуть (F3). О клавишах, выделении и шпаргалке `?` рассказывают только футер и страница `/eisenhower-matrix` (A3). Новичок не знает, что задачи хранятся в браузере и регистрироваться не нужно.
- **У вошедшего пользователя две матрицы.** Local и Cloud живут отдельно, «Copy all tasks to Cloud» копирует задачи с новыми id и оставляет локальные на месте. Переключатель Local/Cloud в меню аккаунта спрятан в «пузыре». После входа локальные задачи тихо пропадают с экрана, после выхода тихо возвращаются. Пользователь не понимает, где его задачи и сколько у него матриц.
- **Шапки нет.** Вместо неё четыре угловые иконки: кнопка темы без имени (X1), кнопка аккаунта «пузырём» на полэкрана с просвечивающими задачами (F4, P5), переключатель вида одной иконкой без подписи. Градиент сверху значит «облако», но это никому не объяснено. Полоса офлайна из R2 висит под угловыми кнопками отдельно от шапки.

## Solution

После R3 интерфейс объясняет себя сам.

- **Добавление там, где смотришь.** Клик по пустому месту любого квадранта, «+» в его заголовке, `N` или `1–4` открывают в квадранте инлайн-поле «Add task to <квадрант>». Enter добавляет задачу в конец квадранта и оставляет поле открытым для следующей, Esc закрывает его. Полоски вставки между задачами больше нет. Большая форма с дедлайном по-прежнему открывается кнопкой «New task».
- **Подсказки внутри матрицы.** В пустом квадранте — пример задач и «Click to add a task» (на touch — «Tap to add»). В заголовке квадранта «click empty space to add», пока пользователь ни разу так не добавил. Под матрицей строка про выделение и `?`. Над пустой матрицей анонимного — «No sign-up — tasks stay in this browser. How it works →». В шпаргалке `?` есть ссылка на `/eisenhower-matrix`.
- **Одна матрица.** Где хранится Matrix, определяет вход. При входе задачи с устройства переносятся в аккаунт (toast «N tasks moved to your account» с Undo). Если в аккаунте уже есть задачи, приложение один раз спрашивает, добавить ли их. Local/Cloud, «Copy to Cloud» и `?cloud` исчезают. После выхода — пустая матрица со строкой «Your tasks are in your Google account».
- **Классическая шапка.** Во всю ширину, всё подписано:
  - слева логотип (от `md` с названием);
  - сегменты Matrix | List;
  - кнопка темы с именем;
  - справа «Sign in» (от `lg` с подписью «Saved only on this device») или аватар с меню: имя, email, «Saved to your Google account», «Sign out».

  Полоса офлайна и Sync error из R2 — часть шапки. Градиент и угловые иконки уходят.

## User Stories

### Добавление (G)

1. Как новичок, я хочу кликнуть по пустому месту любого квадранта и сразу печатать задачу там же, чтобы не искать кнопку и не выбирать квадрант в форме.
2. Как пользователь, я хочу, чтобы Enter добавлял задачу в конец квадранта и оставлял поле открытым, чтобы ввести несколько задач подряд.
3. Как пользователь, я хочу, чтобы Esc закрывал поле без добавления, чтобы передумать.
4. Как пользователь, я хочу, чтобы пустой Enter ничего не добавлял и не ругался, чтобы случайное нажатие не создавало пустых задач.
5. Как пользователь, я хочу видеть «+» в заголовке каждого квадранта, чтобы добавлять в квадрант, где нет свободного места для клика.
6. Как пользователь с выделенной задачей, я хочу, чтобы первый клик по пустому месту только снимал выделение, чтобы снятие выделения не открывало поле неожиданно.
7. Как пользователь, я хочу, чтобы начатый текст переезжал вместе с полем, когда я кликаю по пустому месту другого квадранта, чтобы поменять квадрант, не перепечатывая.
8. Как пользователь, я хочу, чтобы поле с текстом не закрывалось, когда я кликаю мимо, чтобы не терять набранное.
9. Как пользователь клавиатуры, я хочу, чтобы `N` и `1–4` без выделения открывали инлайн-поле в квадранте, а не модальную форму, чтобы добавлять не отрываясь от матрицы.
10. Как пользователь клавиатуры, я хочу, чтобы в пустом квадранте фокус вставал на кнопку «Add a task», чтобы стрелками дойти до любого квадранта, даже пустого.
11. Как пользователь клавиатуры, я хочу, чтобы Tab в полностью пустую матрицу попадал на «Add a task» в Do First, чтобы у пустой матрицы была остановка Tab.
12. Как пользователь клавиатуры, я хочу, чтобы после Complete, Delete или Move последней задачи квадранта фокус вставал на «Add a task» этого квадранта, чтобы не терять место.
13. Как пользователь клавиатуры, я хочу, чтобы Esc из поля возвращал фокус туда, откуда я его открыл, чтобы продолжить с того же места.
14. Как пользователь screen reader'а, я хочу, чтобы поле называлось «Add task to <квадрант>», чтобы знать, куда уйдёт задача.
15. Как пользователь, я хочу видеть у поля одну рамку фокуса (сплошную цвета квадранта), а не две наложенные обводки.
16. Как пользователь телефона, я хочу, чтобы тап по пустому месту ячейки раскрывал квадрант на весь экран с полем внизу, чтобы печатать не в ячейке шириной 170px под экранной клавиатурой.
17. Как пользователь, я хочу, чтобы кнопка «New task» по-прежнему открывала полную форму с дедлайном и выбором квадранта, чтобы сразу задать дедлайн.
18. Как пользователь, я хочу не видеть еле заметных полосок между задачами, потому что они мешают кликать по карточкам и ничего не объясняют.
19. Как вошедший пользователь без сети, я хочу добавлять задачи инлайн-полем так же, как с сетью.

### Снятие выделения (Q)

78. Как пользователь, я хочу снять выделение кликом по любому пустому месту страницы, а не только внутри квадранта, чтобы не целиться в рамку.
79. Как пользователь телефона, я хочу видеть в панели действий кнопку «×», чтобы закрыть панель, когда она закрывает пустое место, а Esc нет.
80. Как пользователь screen reader'а, я хочу явную кнопку «Deselect task», чтобы снять выделение без клавиши Esc.

### Подсказки (I)

20. Как новичок, я хочу видеть в пустом квадранте пример задач, которые туда кладут, чтобы понять метод без чтения инструкции.
21. Как новичок, я хочу видеть в пустом квадранте «Click to add a task» (на touch «Tap to add»), чтобы знать, что по квадранту можно кликнуть.
22. Как новичок с мышью, я хочу видеть в заголовке квадранта «click empty space to add», пока я ни разу так не добавил, чтобы узнать о способе добавления.
23. Как освоившийся пользователь, я хочу, чтобы подсказка в заголовке исчезла навсегда после первой задачи, добавленной кликом по пустому месту, чтобы не видеть лишнего.
24. Как пользователь с мышью, я хочу видеть под матрицей «Click a task to select it · ↑↓←→ move selection · ? all shortcuts», чтобы узнать о выделении, стрелках и шпаргалке.
25. Как пользователь телефона или планшета без мыши, я хочу видеть под матрицей «Tap a task to select it», без клавиш, которых у меня нет.
26. Как владелец ноутбука с сенсорным экраном и мышью, я хочу видеть подсказки для мыши, потому что основной указатель у меня — мышь.
27. Как новичок, я хочу видеть над пустой матрицей «No sign-up — tasks stay in this browser. How it works →», чтобы не искать регистрацию и знать, где лежат задачи.
28. Как новичок, я хочу по ссылке «How it works →» попасть на `/eisenhower-matrix`, чтобы прочитать о методе.
29. Как пользователь, я хочу, чтобы строка «No sign-up…» исчезала с первой задачей, чтобы она не мешала работе.
30. Как вошедший пользователь, я хочу не видеть «No sign-up — tasks stay in this browser», потому что мои задачи в аккаунте.
31. Как вошедший пользователь при холодном старте без сети, я хочу видеть строку «Your tasks are in your account…» из R2 и не видеть примеров в пустых квадрантах, чтобы не решить, что аккаунт пуст.
32. Как пользователь клавиатуры, я хочу найти в шпаргалке `?` ссылку на `/eisenhower-matrix`, чтобы прочитать о методе подробнее.

### Одна матрица и Migration (K)

33. Как анонимный пользователь с задачами, я хочу, чтобы при входе в пустой аккаунт задачи сами переехали в аккаунт, чтобы не делать ничего руками.
34. Как такой пользователь, я хочу увидеть toast «N tasks moved to your account» с Undo, чтобы знать, что произошло, и иметь возможность отменить.
35. Как такой пользователь, я хочу, чтобы этот toast не гас через 6 секунд, а висел до моего первого действия в матрице или пока я его не смахну, чтобы успеть его прочитать.
36. Как пользователь, у которого задачи есть и на устройстве, и в аккаунте, я хочу, чтобы приложение один раз спросило «Add N tasks from this device to your account?», а не объединяло их молча.
37. Как такой пользователь, я хочу, чтобы «Add» добавлял задачи с устройства в конец квадрантов аккаунта, чтобы мои задачи в аккаунте остались наверху.
38. Как такой пользователь, я хочу, чтобы «Don't add» и Esc оставляли задачи на устройстве нетронутыми, чтобы ничего не потерять.
39. Как пользователь, сказавший «Don't add», я хочу, чтобы вопрос не возвращался при каждой перезагрузке, пока я вошёл.
40. Как пользователь, сказавший «Don't add», я хочу после выхода снова видеть задачи устройства, потому что они никуда не делись.
41. Как пользователь, я хочу, чтобы Undo в toast Migration вернул аккаунт и устройство как было до входа, и приложение больше не предлагало перенос, пока я вошёл.
42. Как пользователь, я хочу, чтобы задачи переносились, а не копировались: после переноса на устройстве их нет, дублей в аккаунте нет.
43. Как пользователь с плохой сетью, я хочу, чтобы задачи устройства не стирались, пока облако не подтвердило перенос, чтобы не потерять их, если связь оборвётся.
44. Как пользователь, закрывший вкладку до подтверждения переноса, я хочу, чтобы перенос не задвоил задачи и не спросил меня второй раз.
45. Как пользователь, чей перенос облако отклонило, я хочу, чтобы задачи остались на устройстве и появилась полоса Sync error, чтобы знать о проблеме.
46. Как пользователь, вошедший до R3 и имеющий и локальные, и облачные задачи, я хочу, чтобы при первом открытии после релиза мне задали тот же вопрос, чтобы локальные задачи не остались невидимыми.
47. Как пользователь, я хочу не видеть нигде «Cloud Matrix», «Local Matrix» и «Copy all tasks to Cloud», чтобы не думать о двух матрицах.
48. Как вошедший пользователь, я хочу видеть в меню аккаунта строку «Saved to your Google account», чтобы знать, где мои задачи.
49. Как анонимный пользователь, я хочу видеть в панели входа «Saved only on this device», чтобы знать, что задачи не в облаке.
50. Как пользователь, только что вышедший из аккаунта, я хочу видеть пустую матрицу со строкой «Your tasks are in your Google account. Sign in to see them.», а не пугаться пустоты.
51. Как такой пользователь, я хочу, чтобы эта строка исчезла, когда я добавлю задачу или войду, чтобы она не висела вечно.
52. Как пользователь старой ссылки с `?cloud`, я хочу, чтобы главная открылась как обычно.
53. Как пользователь screen reader'а, я хочу, чтобы вопрос при входе был нативным `<dialog>` с инертным фоном, чтобы не потерять его.

54. Как новичок, я хочу видеть наверху обычную шапку во всю ширину, чтобы сразу понять, где навигация и настройки.
55. Как пользователь, я хочу видеть слева логотип, а на широком экране и название «Eisenhower Matrix», чтобы знать, где я.
56. Как пользователь на других страницах (`/eisenhower-matrix`, `/privacy`), я хочу вернуться к матрице кликом по логотипу.

58. Как пользователь телефона, я хочу, чтобы сегменты вида показывали только иконки, но не теряли доступных имён, чтобы шапка помещалась в 390px.
59. Как пользователь клавиатуры, я хочу переключать сегменты стрелками ←→ как вкладки, а Tab уводил дальше, чтобы шапка не была лишней чередой остановок.
60. Как пользователь screen reader'а, я хочу, чтобы кнопка темы называлась «Switch to dark theme» / «Switch to light theme», чтобы понимать, что она делает.
61. Как анонимный пользователь, я хочу видеть справа кнопку «Sign in» со значком Google, которая сразу запускает вход.

63. Как вошедший пользователь, я хочу видеть свой аватар, по клику — меню с именем, email, «Saved to your Google account» и «Sign out».
64. Как вошедший пользователь, я хочу, чтобы меню закрывалось кликом снаружи и Esc, а не заслоняло полэкрана матрицы.
65. Как пользователь клавиатуры, я хочу работать с меню аккаунта по стандарту menu button: Enter, Space или ↓ открывают его, Esc закрывает и возвращает фокус на аватар, Tab закрывает.
66. Как вошедший пользователь с Pending changes, я хочу, чтобы «Sign out» в новом меню открывал тот же диалог из R2, а «Stay signed in» возвращал фокус на аватар.
67. Как вошедший пользователь, я хочу, чтобы полоса офлайна и Sync error была частью шапки и оставалась видна при прокрутке, не перекрывая матрицу.

### Доступность и проверка

73. Как пользователь screen reader'а, я хочу, чтобы шапка была ориентиром `banner`, а сегменты вида — `tablist` с `tab` и `aria-selected`.
74. Как слабовидящий пользователь, я хочу, чтобы все новые тексты (подсказки, примеры, подписи шапки) имели контраст ≥ 4.5:1 в обеих темах.
75. Как пользователь с `prefers-reduced-motion`, я хочу, чтобы меню аккаунта, поле и подсказки появлялись без движения.

77. Как разработчик, я хочу проверять Migration в jest на той же смонтированной главной с фейком облака, включая офлайн, отказ и перезагрузку, чтобы перенос не ломался незаметно.

### Где живёт код

По [архитектуре](../../docs/agents/architecture.md), как ориентир (тикет может решить иначе):

- инлайн-поле и «+» — фича добавления задачи (существующий слайс `addTask`). Квадрант (сущность) даёт для них место, но фичу не импортирует: её подставляет матрица-виджет;
- пример и CTA пустого квадранта — отображение квадранта; строка под матрицей и строка над пустой матрицей — виджет матрицы; флаг подсказки «click empty space to add» — в сохраняемом `uiStore`;
- Migration — слайс по термину глоссария (`features/migration`). Чистая функция плана лежит в его `lib`, вопрос при входе — в его `ui`;
- шапка — `widgets/header`. Меню аккаунта — в `features/auth`, кнопка темы — в `features/toggleTheme`, сегменты — в `features/switchViewMode`. Унаследованные `entities/authIndicator`, `entities/themeToggleButton`, `shared/ui/bubbleCornerButton` L переписывает, поэтому старые места удаляются в том же срезе.

### G. Добавление кликом по пустому месту

Решения: [тикет 05](../ui-ux-audit/issues/05-task-actions-discoverability.md), раздел «Добавление»; семантика — [тикет 11](../ui-ux-audit/issues/11-accessibility-baseline.md).

- **Пустое место** — любая точка квадранта, кроме карточки, кнопок заголовка, «+N below» и самого поля: промежутки между карточками, место под последней задачей, пустой квадрант целиком.
- **Клик по пустому месту без выделения** открывает инлайн-поле в конце списка этого квадранта (после последней задачи, внутри прокручиваемой области). Список прокручивается так, чтобы поле было видно, и «+N below» пересчитывается.
- **Клик по пустому месту при выделенной задаче** только снимает выделение, поле не открывается (дополнение спеки). Так клик по пустому месту не делает два дела сразу. Это заменяет переходное решение R1 для пустых квадрантов, где клик и снимал выделение, и открывал форму.
- **Поле одно на странице.** Открытие в другом квадранте переносит его туда вместе с набранным текстом (дополнение спеки).
- **Enter** добавляет задачу с обрезанным текстом в конец квадранта, очищает поле и оставляет его открытым с фокусом. Добавленная задача не выделяется. Toast нет: добавление молча, по [тикету 12](../ui-ux-audit/issues/12-toast-behaviour.md). Пустой текст и текст из пробелов Enter игнорирует без сообщения об ошибке. Длина ограничена 200 символами на уровне поля.
- **Esc** закрывает поле без добавления. **Уход фокуса** (клик мимо, Tab) закрывает пустое поле. Поле с текстом остаётся открытым, пока пользователь не нажмёт Enter или Esc (дополнение спеки).
- **Куда уходит фокус после Esc** (дополнение спеки): туда, откуда поле открыли. Это «+» квадранта, «Add a task», задача (при `N`) или прежнее место фокуса (при `1–4` без выделения). После клика по пустому месту фокус уходит на «+» этого квадранта. На `body` фокус не падает.
- **Открытие поля снимает выделение**: панель действий закрыта, пока поле открыто.
- **«+» в заголовке квадранта** — кнопка с доступным именем «Add a task to <квадрант>», открывает поле. Она стоит вне Tab-порядка (`tabindex="-1"`): матрица остаётся одной остановкой Tab, клавиатура добавляет через `N`, `1–4` и «Add a task» (дополнение спеки). В ячейке телефона «+» — соседняя кнопка рядом с кнопкой-заголовком «Open … full screen», не вложенная в неё. Касаемая цель не меньше 44×44.
- **`N` и `1–4` без выделения** открывают инлайн-поле вместо модальной формы: `N` в Do First или в квадранте последнего выделения, `1–4` в квадранте N. С выделением `1–4` переносят задачу, как в R1. Переходное решение R1 («до среза G открывает форму добавления») снимается.
- **Кнопка «New task» (FAB)** по-прежнему открывает модальную форму с выбором квадранта и дедлайном. В инлайн-поле дедлайна нет. Параметр вставки по индексу (`taskInsertIndex`) уходит вместе с `InsertTaskZone`.
- **Пустой квадрант** показывает кнопку «Add a task», которая открывает поле. Она участвует в roving tabindex матрицы:
  - стрелки ←→ заходят в пустой квадрант на эту кнопку (пустой квадрант больше не пропускается), панель при этом скрыта;
  - Tab в полностью пустую матрицу встаёт на «Add a task» в Do First;
  - Enter, Space и `N` на ней открывают поле.

  Переходные решения R1 «пустые квадранты в roving tabindex не участвуют» и «у пустой матрицы нет остановки Tab» снимаются. Текст и вид этой кнопки дорабатывает I.
- **Фокус после Complete, Delete и Move**: если квадрант опустел, фокус встаёт на его «Add a task». Это заменяет правило R1 «ближайшая задача соседнего квадранта». Правила «следующая, иначе предыдущая» и «после Undo — восстановленная» не меняются. Правило J1 для чужих изменений (исчезнувшая Selected Task → фокус на контейнер матрицы) не меняется.
- **Индикатор фокуса поля** — один: пунктирная рамка цвета квадранта становится сплошной, браузерный outline выключен. Контраст рамки не меньше 3:1 к фону квадранта в обеих темах.
- **Телефон (< 640px, сетка 2×2)** (дополнение спеки):
  - тап по пустому месту ячейки или «+» раскрывает квадрант на весь экран (R1, тикет 16) с полем в конце списка и фокусом в нём;
  - «Back to matrix» закрывает поле;
  - пока поле открыто, FAB скрыт, как при открытой панели.

  Причина: в ячейке шириной около 170px под экранной клавиатурой поле не видно. В раскрытом квадранте поле ведёт себя как на desktop.
- **`InsertTaskZone` удаляется** вместе с зонами между карточками. Вставка между задачами — добавить и перетащить.
- **Страница `/eisenhower-matrix`**, раздел «How to use the app», и шпаргалка `?` описывают новое добавление: клик по пустому месту, «+», `N`/`1–4` открывают поле в квадранте, Enter добавляет следующую, «New task» — форма с дедлайном.
- **Вошедший пользователь:** поле пишет через те же действия стора. Запись не ждёт облака (R2), поле работает без сети.

### Q. Снятие выделения

Дополнение спеки. Решение R1 ([тикет 05](../ui-ux-audit/issues/05-task-actions-discoverability.md)): «повторный клик, клик по пустому месту или Esc снимает выделение». В R1 «пустое место» оказалось только внутри рамки квадранта, а на телефоне панель закрывает нижний ряд ячеек и Esc нет.

- **Клик вне задачи.** Клик или тап по любому неинтерактивному месту страницы снимает выделение: поля страницы, зазоры между квадрантами, подписи осей, пустые места шапки и заголовка, место под матрицей, футер. Внутри квадранта правило G не меняется.
- **Исключения — всё, что делает своё действие.**
  - Другая карточка выделяет её.
  - Кнопки панели выполняют действие.
  - Toast выполняет Undo.
  - «+N below» прокручивает (H).
  - Модальные диалоги перехватывают клик.
  - Интерактивные элементы вне матрицы (тема, List view, Sign in, ссылки) и «Open … full screen» выделение не трогают: переключение темы не теряет выделение, а раскрытый квадрант сам следует за выделением (H).
  - «+» квадранта снимает выделение, потому что открывает поле (G).
- **Кнопка «×» в панели действий.** Доступное имя «Deselect task»: имя называет действие над задачей, панель — лишь следствие выделения (**Selected Task** в `CONTEXT.md`). `aria-keyshortcuts="Escape"`.
  - Desktop: последняя в полосе, после Delete, через разделитель, с подсказкой `Esc`.
  - Телефон: справа в строке с текстом задачи, цель не меньше 44×44.
  - Работает везде, где есть панель, включая List view.
- **Фокус.**
  - После «×» фокус на карточке этой задачи без выделения, в том же состоянии, что после Esc с задачи. Возврат фокуса на карточку не должен выделять её снова, хотя обычно фокус на карточке выделяет.
  - После клика по пустому месту фокус специально не переносится.
- Шпаргалка `?` и `/eisenhower-matrix` упоминают «×» рядом с Esc.

### I. Подсказки внутри матрицы

Решения: [тикет 08](../ui-ux-audit/issues/08-first-visit-onboarding.md), таблица «Подсказки и когда они видны» и строка «без регистрации».

- **Пустой квадрант:** строка примеров из словаря квадрантов (поле `examples`, например «e.g. Server is down, tax return due tomorrow»). Словарь общий со страницей `/eisenhower-matrix`, поэтому примеры совпадают. Под ней кнопка из G с видимым текстом «Click to add a task» (мышь) или «Tap to add» (touch).
  - Доступное имя кнопки совпадает с видимым текстом (WCAG 2.5.3), квадрант передаётся описанием через название квадранта (дополнение спеки).
  - Видно всегда, пока квадрант пуст.
- **«click empty space to add»** — мелким текстом в заголовке квадранта. Условия показа (дополнение спеки: «широкие экраны» из тикета 05):
  - только при основном указателе-мыши и от 640px;
  - исчезает навсегда после первой задачи, добавленной кликом по пустому месту. Добавление через «+», клавиши, «Add a task» или FAB флаг не ставит.

  Флаг хранится в localStorage устройства (в сохраняемом `uiStore`) и не синхронизируется. Вход, выход и стирание кэша облака его не сбрасывают.
- **Строка под матрицей**, видна всегда в виде Matrix:
  - мышь: «Click a task to select it · ↑↓←→ move selection · ? all shortcuts»;
  - touch: «Tap a task to select it».

  Touch определяется по `(hover: none) and (pointer: coarse)`, а не по ширине. Строка — неинтерактивный текст. Она не встаёт в Tab-порядок и не ломает правило R1 «Undo — следующая остановка Tab после матрицы» (дополнение спеки). В List view её нет до среза N, где в List view придёт выделение.
- **Строка над пустой матрицей:** «No sign-up — tasks stay in this browser. How it works →», где «How it works →» — ссылка на `/eisenhower-matrix`.
  - Видна анонимному пользователю, пока в матрице нет ни одной активной задачи, и исчезает с первой задачей.
  - Рендерится только после восстановления стора из localStorage, поэтому у вернувшегося пользователя с задачами не мелькает.
  - Вошедшему не показывается: для него она неправда.
  - Если строка K «Your tasks are in your Google account…» активна, показывается она вместо «No sign-up…» в том же месте.
- **Холодный старт вошедшего без сети** (R2, J2): над матрицей строка «Your tasks are in your account. They'll appear when you're back online.». Примеров в пустых квадрантах нет, чтобы аккаунт не выглядел пустым. «Click to add a task» остаётся: добавлять можно (дополнение спеки, по комментарию из тикета 17 в тикете 08).
- **Шпаргалка `?`** получает ссылку «How the Eisenhower Matrix works →» на `/eisenhower-matrix`. Ссылка в конце диалога и доступна по Tab внутри него.
- **Футер** не меняется: ссылка на `/eisenhower-matrix` там уже есть (R1).
- Контраст всех подсказок не меньше 4.5:1 на фонах квадрантов и страницы в обеих темах. Цвет — не единственный признак: подсказки подписаны текстом.

### K. Одна матрица и Migration

Решения: [тикет 03](../ui-ux-audit/issues/03-one-matrix-model.md), строка «Migration» в [тикете 17](../ui-ux-audit/issues/17-offline-ux.md), toast — [тикет 12](../ui-ux-audit/issues/12-toast-behaviour.md).

**Одна матрица в сторе.**

- Выбора Storage больше нет: вошёл — Matrix в облаке, не вошёл — на устройстве. Признак `activeState` и действия `switchToLocalTasks`/`switchToFirebaseTasks` удаляются. Storage выводится из того, есть ли вошедший пользователь, с которым облачная подписка из R2 уже знает `uid`.
- Все действия стора, Completed, List view и панель читают и пишут «текущую матрицу» по этому признаку.
- Локальная матрица по-прежнему хранится persist-ом `tasksStore` в localStorage, облачная — облачным клиентом из R2. Схема документов Firestore и ключи localStorage не меняются.
- **Удаляются:**
  - фича `switchTaskSource` вместе с обработкой `?cloud` (параметр просто игнорируется, главная открывается как обычно);
  - сущность `taskSourceTabs`;
  - фича `copyTasksToCloud` и действие `copyLocalTasksToFirebaseAction`;
  - плитки «Cloud Matrix» / «Local Matrix» в меню аккаунта.
- **Градиент `SyncGlow`** до среза L показывается при вошедшем пользователе вместо `activeState === 'firebase'`. Удаляет его L.

**Когда запускается Migration** (дополнение спеки). Одно правило для входа кнопкой, для входа в другой вкладке и для пользователей, вошедших до R3, у которых остались и локальные, и облачные задачи. Migration нужна, когда:

- пользователь вошёл;
- на устройстве есть задачи, которых нет в облаке (сравнение по id);
- для этого `uid` на устройстве не записан отказ.

**Что решает Migration.** Сравнивать с облаком можно, только когда облако известно: пришёл снимок с сервера или из кэша устройства с задачами (то же условие, что снимает лоадер в R2). Облако «пусто», если в нём нет задач, кроме задач с этого устройства (они там бывают после оборванной Migration).

- **Облако пусто** → перенос сразу, без вопроса.
- **В облаке есть свои задачи** → вопрос.
- **Все задачи устройства уже в облаке** (вкладку закрыли после записи, но до очистки) → очистка устройства без toast и вопроса. Так повторный запуск не задваивает задачи и не спрашивает второй раз.

**План переноса** — чистая функция. Вход: задачи устройства (активные и Completed) и снимок облака. Выход: решение (`none` | `move` | `ask`), число задач N и список `TaskChange` из R2.

- Задачи переносятся **с теми же id** (тикет 03: «при переносе нужно наоборот»), с тем же текстом, `createdAt`, дедлайном и `completedAt`.
- При пустом облаке порядок в квадрантах сохраняется.
- При «Add» задачи устройства встают в конец каждого квадранта после облачных, Completed объединяется по `completedAt`.
- Задача с id, который уже есть в облаке, не пишется второй раз.
- Вся Migration — одна запись (батчами по 500 внутри облачного клиента).

**Перенос** (`move` или «Add»):

1. Задачи записываются в облако и сразу видны в матрице из подписки (облачная матрица показывает их из кэша с Pending changes).
2. Сразу показывается toast «N tasks moved to your account» (для одной задачи «1 task moved to your account») с Undo. N — все перенесённые задачи, активные и Completed.
3. Toast Migration не гаснет через 6 с. Он висит до первого изменения матрицы (добавить, изменить, Complete, Delete, Move, Restore), до смахивания или пока его не заменит следующий toast (слот один). Выделение задачи изменением не считается (дополнение спеки). `Ctrl/Cmd+Z` отменяет Migration, пока toast виден.
4. **Локальная копия очищается только после подтверждения сервером.** После `waitForPendingWrites` с устройства удаляются те задачи, которые есть в облаке по снимку с сервера (дополнение спеки). Облачный клиент R2 резолвит `waitForPendingWrites` и при отказе, как Firestore. Поэтому отказанная запись не должна стирать задачи: SDK убирает её из локального вида, и по снимку этих задач в облаке нет.
   - Без сети очистка ждёт. Полоса показывает офлайн, затем «Syncing…».
   - Закрыли вкладку до подтверждения — при следующем запуске работает правило «все задачи устройства уже в облаке».
   - Худший случай — дубль на устройстве, но не потеря (тикет 17).
5. **Отказ облака** — это Sync error из R2 (красная полоса, «Reload»). Задачи остаются на устройстве, их увидят после выхода. Повтор — при следующем запуске по общему правилу.

**Вопрос при непустом облаке** — нативный `<dialog>` на общем модальном компоненте:

- заголовок: «Add N tasks from this device to your account?»;
- пояснение: «Your account already has tasks. The tasks from this device will be added after them.»;
- кнопки «Add» и «Don't add»; фокус при открытии на «Add».

Поведение (дополнение спеки):

- **«Add»** — перенос, как описано выше, с тем же toast и Undo.
- **«Don't add» и Esc** не трогают ни облако, ни устройство. На устройстве записывается отказ для этого `uid`, так что перезагрузки вопрос не повторяют. Отказ стирается при выходе: при следующем входе вопрос задаётся снова, а задачи устройства после выхода снова видны анонимной матрицей.
- **После закрытия** фокус уходит на кнопку аккаунта, потому что «Sign in», открывавшая вход, исчезла. На `body` фокус не падает.

**Undo Migration** (дополнение спеки):

- удаляет перенесённые задачи из облака;
- возвращает задачи на устройство, если их уже очистили;
- записывает отказ для этого `uid`, как «Don't add».

Вошедший пользователь после Undo видит облако как до входа. Его задачи устройства вернутся после выхода. Undo — ещё одна запись и без сети работает так же (R2).

**Выход** (дополнение спеки о том, когда видна подсказка):

- При выходе через «Sign out» (в этой или другой вкладке) устройство запоминает, что пользователь вышел. Сама очистка кэша Firestore — из R2.
- Пока анонимная матрица пуста, над ней строка «Your tasks are in your Google account. Sign in to see them.» с кнопкой «Sign in», которая запускает вход через Google.
- Строка исчезает с первой добавленной задачей или со входом.
- Истёкшая сессия (J3) строку не показывает: там красная полоса «Sign in again».
- Если после выхода на устройстве есть задачи (был «Don't add» или Undo), показывается обычная матрица с ними, строки нет.

**Pending changes и выход.** Незавершённая Migration не теряет задачи при «Sign out anyway»: локальная копия ещё не очищена. Диалог выхода R2 не меняется и считает Migration одной записью.

**Меню аккаунта до L.** В текущем угловом меню плитки Local/Cloud заменяются строкой «Saved to your Google account». В панели анонимного пользователя текст про «cloud matrix» заменяется на «Saved only on this device. Sign in with Google to keep your tasks in your account and use them on other devices.». Остальное меню L переделывает целиком.

## Testing Decisions

**Что такое хороший тест.** Как в R1 и R2:

- тест проверяет только внешнее поведение — что видит и делает пользователь и что слышит screen reader (роли, доступные имена, тексты, фокус);
- во внутреннее состояние сторов, имена хуков и флаги localStorage тесты не лезут. Флаг проверяется через `reload()`, а не чтением ключа;
- собственные модули не мокаются, поиск идёт по ролям и именам;
- мокаются только внешние границы: облачный клиент матрицы, клиент аутентификации, роутер, `matchMedia`.

**Seams (согласованы).**

1. **Главный seam — смонтированная главная** (`renderHomePage` с фейком облака из R2). Новых границ R3 не вводит, seam получает три небольших расширения:
   - **вход посреди теста.** Анонимный старт с `tasks` на устройстве и `cloud.tasks` на сервере, затем клик «Sign in». `fakeAuthClient.signInWithGoogle` уже умеет входить. Нужно, чтобы опция `cloud` работала и без `signedIn` и задавала, что лежит на сервере у пользователя, который войдёт. Ещё нужно, чтобы `lastUser` можно было задать без старта во вход. Имена решает тикет;
   - **email пользователя** в `SignedInUser` и в фейке — для меню L;
   - **флаги устройства** (подсказка «click empty space to add», отказ от Migration, «вышел») переживают `reload()`, потому что `reload()` не чистит localStorage. Отдельных опций для них нет: тест доводит до нужного состояния действиями пользователя.

   Указатель мышь/touch уже задаётся `viewport.pointer`, ширина — `viewport.width`.
2. **Тонкий seam — план Migration.** Чистая функция «задачи устройства + снимок облака → решение, N, `TaskChange[]`» проверяется таблицей, как `actionChanges` в R2. Случаи:
   - облако пусто;
   - облако с задачами;
   - все задачи устройства уже в облаке;
   - часть уже в облаке;
   - только Completed;
   - порядок при «Add»;
   - объединение Completed по `completedAt`;
   - те же id.

   Это единственная логика, которую фейк не покрывает целиком: главный seam проверяет, что решение применено, а таблица — все сочетания.

Других seams нет. Шапка, поле и подсказки проверяются только главным seam, отдельных компонентных тестов нет.

- **Серьёзность:** все пять срезов — S2. Новичок проходит сценарии и без них, но путается (M4, F3, A3, F4, P5), а X1 нарушает WCAG. Потерь данных R3 не закрывает. Зато K не должен их создать, поэтому правило «очистка только после подтверждения» проверяется и в jest, и вручную.
- **K — самый рискованный срез.** Удаление `activeState` трогает каждое действие стора, Completed, List view, панель и drag. Имеет смысл нарезать K на тикеты так, чтобы сначала шло «одна матрица без переключателя» (без переноса, локальные задачи вошедшего пока не видны), а затем перенос. Но PR в `main` — только после всего среза: промежуточное состояние прячет задачи устройства после входа, и в прод его выпускать нельзя.
- **Время решения Migration.** Вошедший пользователь, открывший приложение без сети и без кэша, не увидит задач устройства, пока не ответит сервер. Его матрица в это время — холодный старт R2. Спросить, не зная облака, нельзя: вопрос мог бы оказаться лишним. Это принятая цена.
- **Флаги устройства** (подсказка «click empty space to add», отказ от Migration по `uid`, «вышел») лежат в localStorage вне persist задач. Стирание кэша Firestore при выходе (R2) их не трогает, отказ стирает только сам выход.
- **Возможные расхождения с R1**, которые срезы меняют сознательно:
  - клик по пустому квадранту при выделении (G);
  - клик вне квадранта снимает выделение, в панели кнопка «×» (Q);
  - фокус в опустевшем квадранте (G);
  - пустые квадранты в roving tabindex (G);
  - `N` и `1–4` без выделения открывают поле, а не форму (G);
  - «Logout» → «Sign out» (L).

  Тесты и чек-лист R1 по этим пунктам обновляются в своих срезах.
- ADR в репозитории нет (`docs/adr/` отсутствует), противоречий нет. Термины глоссария хватает. Новый термин не вводится: «инлайн-поле» — деталь UI, а не понятие предметной области.

# 06: Смена вида: прокрутка наверх и без вспышки

**What to build:** Пользователь при переключении Matrix ↔ List всегда видит новый вид сверху, а сохранённый List открывается сразу, без мелькания матрицы. Срез N [спеки R4](../spec.md), раздел «N. List view по секциям» (Переключение вида); решение: [Роль List view](../../ui-ux-audit/issues/10-list-view-role.md); долг из Comments [тикета 14 R3](../../ux-r3/issues/14-view-segments.md).

**Blocked by:** 03 (по коду; в срезе идёт последним, PR среза N — после 05 и 06)

**Status:** resolved

- [x] Смена вида вкладками (клик, ←→) прокручивает страницу наверх сразу, без плавной прокрутки (L4). Прокрутка — внутри одного пути смены вида, чтобы O мог добавить к нему явное исключение.
- [x] Смена вида по-прежнему снимает выделение и закрывает поле. По умолчанию, и на телефоне, Matrix.
- [x] Пока `uiStore` не прочитан из localStorage, область вида показывает лоадер, ни одна вкладка не выбрана, место под вкладками зарезервировано (шапка не прыгает). После чтения сразу сохранённый вид, `tablist` с одной `aria-selected` вкладкой в тот же кадр. Ошибок гидратации нет.
- [x] Главный seam: смена вида вызывает `scrollTo` наверх; `reload()` с сохранённым List: до чтения стора нет выбранной `tab` и нет матрицы, после — выбран «List» и показан List view, Matrix ни разу не рендерилась; axe во время лоадера (`aria-controls` указывает на панель).
- [x] Чек-лист: раздел N «Смена вида» — прокрутка наверх из середины длинной матрицы и списка, нет вспышки Matrix при сохранённом List на медленной сети (DevTools → Slow 3G).
- [ ] Закрыт последний тикет среза N (вместе с 05): предложить PR `ux-r4` → `main` с проверкой на Vercel preview.

## Comments

**Что сделано.**

- **Один путь смены вида** — `features/switchViewMode/model/switchView`: `setViewModeAction` (как в R3, снимает выделение и закрывает поле) и `window.scrollTo({ top: 0, behavior: 'instant' })`. Клик и ←→ во вкладках идут через него, `setViewModeAction` больше никто не вызывает. Если вид не меняется (клик по выбранной вкладке), ничего не происходит: ни прокрутки, ни снятия выделения.
- **Без вспышки** — `useIsUIStoreRestored` в `uiStore` по образцу `useIsTaskStoreRestored`: `useSyncExternalStore` с серверным снимком `false`. Пока он `false` (серверный HTML и рендер гидратации), `TaskMatrix` показывает лоадер, `ViewTabs` не выбирают вкладку (место то же, подсвечивается только выбранная), в Tab-порядке первая вкладка, `ViewPanel` без `aria-labelledby`. Следующим рендером — сохранённый вид, вкладки и панель вместе. Ошибок гидратации нет: до чтения стора разметка не зависит от `viewMode`.
- **Лоадер** `LoaderFullScreen` получил `role="status"` и скрытый текст «Loading…»: раньше screen reader его не замечал, и тест не мог отличить лоадер от пустой панели.
- **Тесты** — `renderHomePage` получил `reloadFromServer()`: `renderToString` (node-сборка, как в `serverPages.test`), затем `render(…, { hydrate: true })`; возвращает копию серверного HTML. В `viewSegments.test`: `scrollTo` наверх на клик и ←, нет прокрутки на выбранной вкладке, смена вида снимает выделение и закрывает поле с текстом; с сохранённым List — в серверном HTML лоадер в `tabpanel`, ни одной `aria-selected="true"`, нет матрицы; после гидратации выбран «List» и показаны секции, `MutationObserver` не видел осей матрицы ни разу, `console.error` не вызывался; axe на серверном HTML.
- **Чек-лист** — раздел N «Смена вида».

**Проверено в Chrome** (dev на 3100, изолированный контекст, 56 задач): из середины матрицы и списка смена вида даёт `scrollY` 0, клик по выбранной вкладке прокрутку не трогает. Slow 3G без кэша при сохранённом List: в серверном HTML обе вкладки `aria-selected="false"`, после гидратации сразу List, текста осей матрицы в DOM не было ни разу; ошибок и предупреждений в консоли нет. VoiceOver и телефон не проверял — пункты чек-листа.

**Для O.** Исключение «✓ N completed →» (без прокрутки) добавлять в `switchView`, например опцией, а не прямым вызовом `setViewModeAction`: иначе путь разойдётся.

**Ревью (стандарты и спека), что оставлено.** `useIsUIStoreRestored` повторяет `useIsTaskStoreRestored` строка в строку; общий `usePersistRestored(store)` не заводили ради двух копий. Правило «до чтения стора вида нет» проверяется в трёх местах (`ViewTabs`, `ViewPanel`, `TaskMatrix`); хук вида «или null» свёл бы их, но `TaskMatrix` всё равно ждёт ещё и аккаунт. `switchView` в сегменте `model`, как команды `features/undo/model`. Телефонный «по умолчанию Matrix» отдельным тестом не проверен: значение по умолчанию одно на все ширины.

# R4 «Полировка»

Status: ready-for-agent

Четвёртый и последний релиз по [спеке UX-изменений](../ui-ux-audit/spec.md). В него входят три среза, у каждого свой PR `ux-r4` → `main`:

- **M «Дедлайны и просрочка»**;
- **N «List view по секциям»**;
- **O «Completed как секция List view»**.

Решения приняты в тикетах аудита и здесь не пересматриваются:

- [Дедлайны и просрочка](../ui-ux-audit/issues/15-deadlines-overdue.md) — M;
- [Роль List view](../ui-ux-audit/issues/10-list-view-role.md) — N;
- [Блок Completed](../ui-ux-audit/issues/14-completed-section.md) — O;
- [Единая модель деструктивных действий](../ui-ux-audit/issues/04-destructive-actions.md) и [Поведение toast-уведомлений](../ui-ux-audit/issues/12-toast-behaviour.md) — диалог «Delete all» и toast Restore в O;
- [Обнаружимость действий над задачей](../ui-ux-audit/issues/05-task-actions-discoverability.md) — выделение и панель в N и O;
- [Онбординг первого визита](../ui-ux-audit/issues/08-first-visit-onboarding.md) — пример и CTA в пустой секции N;
- [Минимальная планка доступности](../ui-ux-audit/issues/11-accessibility-baseline.md) — общая планка для всех срезов.

Спека собирает эти решения в один документ для реализации и добавляет то, чего в тикетах нет:

- как хранится дедлайн без времени и что считают старые задачи;
- точные границы OVERDUE / DUE TODAY / DUE SOON и когда бейдж обновляется сам;
- какие даты ставят чипы «This weekend» и «Next week»;
- как клавиатура ходит по секциям, если какие-то свёрнуты или пусты;
- что происходит с выделением и полем, когда секция сворачивается;
- как List view не мигает сохранённым видом до гидратации;
- куда уходит фокус, когда Completed опустел;
- текст и фокус диалога «Delete all»;
- тестовые seams и разбивку на срезы.

Такие дополнения помечены словами «(дополнение спеки)».

Термины взяты из [CONTEXT.md](../../CONTEXT.md): **Matrix**, **List view**, **Quadrant**, **Task**, **Selected Task**, **Deadline**, **Overdue**, **Completed Task**, **Storage**, **Pending changes**, **Sync error**. Ветки и мерж — по правилам `CLAUDE.md`: ветка `ux-r4` от свежего `main`, тикеты коммитятся в `ux-r4`, PR в `main` открывается после последнего тикета среза.

## Problem Statement

После R3 матрица объясняет себя сама, но три места остались недоделанными.

- **Дедлайн трудно прочитать и неудобно задать.** На карточке только относительное время («in 3 days», «2 hours overdue»), точная дата спрятана в `title` в формате `dd/MM/yyyy HH:mm`, зашитом для всех локалей. «Скоро» ничем не отмечено. В форме одно поле даты-времени на `react-datepicker` с пресетами +3h / +24h / +3d / +1w: время обязательно, «завтра» без часа не задать, на телефоне календарь не системный и не проверен. В List view на карточке по-прежнему жирная дата создания (M1), которая спорит с дедлайном.
- **List view — не та же матрица.** Это лента карточек, где квадрант виден только по цвету (L1). Порядок задаёт select «Sort by: Date / Importance» и ещё один select направления, без подписей для screen reader'а (L2, axe не проходит). Текст по центру, длинный список трудно просматривать (L3). У каждой карточки свои кнопки, выделения, панели и клавиш матрицы нет. После переключения вида страница остаётся на старом скролле (L4). Сохранённый List сначала рисуется как Matrix и перескакивает.
- **Completed почти не найти и неудобно разбирать.** Блок под матрицей виден только краем внизу первого экрана (M7). Задачи идут от старых к новым, свежая оказывается внизу (C3). При раскрытии страница сама прокручивается, Restore и Delete видны только при наведении, дата создания спрятана за hover (C4). Restore возвращает задачу в конец квадранта, где её не видно. «Delete all» — последний `window.confirm` в приложении.

## Solution

После R4 все основные экраны доведены до планки.

- **Дедлайн читается словами.** На карточке абсолютная дата в локали браузера (`Fri 25 Sept, 9:00`, год только если не текущий, время только если задано) и перед ней бейдж `⚠ OVERDUE`, `DUE TODAY` или `DUE SOON`. У просроченной карточки ещё заливка бейджа и толстая левая полоса, но статус понятен и без цвета. В форме чипы No deadline / Today / Tomorrow / This weekend / Next week, нативное поле даты с видимой подписью и необязательное время кнопкой «+ Add time». Под полями превью «Shows on card as: …». Дедлайн без времени значит «до конца дня».
- **List view — матрица сверху вниз.** Четыре секции в порядке приоритета с липкими заголовками: значок 2×2, название, критерии, счётчик, «+». Секции сворачиваются, это запоминается на устройстве. Внутри секции задачи в том же порядке, что в квадранте, сортировок нет. Выделение, панель действий, клавиши и инлайн-поле работают как в матрице, без drag. Одна колонка по центру, текст по левому краю. При смене вида страница прокручивается наверх, выбранный вид открывается сразу, без вспышки другого.
- **Completed — последняя секция List view.** «Completed (N)», по умолчанию свёрнута. Из Matrix к ней ведёт строка «✓ N completed →» под матрицей. Новые сверху, первые 50 и «Show more». Выделение и панель Restore / Delete: Restore возвращает задачу в начало исходного квадранта с toast «Restored to Schedule» и Undo, Delete удаляет сразу с Undo. У строки подпись исходного квадранта словом и дата завершения. «Delete all» — модальный диалог на нативном `<dialog>`, `window.confirm` в приложении больше нет.

## User Stories

### Дедлайны (M)

1. Как пользователь, я хочу видеть на карточке дату дедлайна полностью (`Fri 25 Sept`), а не только «in 3 days», чтобы сразу знать, какой это день.
2. Как пользователь, я хочу видеть день недели в дате, чтобы не считать в уме, когда это.
3. Как пользователь, я хочу видеть год только для дедлайна не в текущем году, чтобы карточка была короче.
4. Как пользователь, я хочу видеть время только у дедлайна, для которого я его задал, чтобы «завтра» не превращалось в «завтра, 00:00».
5. Как пользователь в США, я хочу видеть дату и время в привычном мне формате (12 часов, месяц перед числом), а не в зашитом `dd/MM/yyyy HH:mm`.
6. Как пользователь, я хочу видеть бейдж `⚠ OVERDUE` у просроченной задачи, чтобы заметить её сразу.
7. Как пользователь, я хочу видеть `DUE TODAY` у задачи со сроком сегодня, чтобы не забыть о ней до вечера.
8. Как пользователь, я хочу видеть `DUE SOON` у задачи со сроком завтра или послезавтра, чтобы подготовиться заранее.
9. Как пользователь, я хочу не видеть бейджа у задачи со сроком дальше, чтобы бейдж значил что-то важное.
10. Как дальтоник, я хочу понимать просрочку по слову, а не по красному цвету.
11. Как пользователь screen reader'а, я хочу слышать статус и дату вместе с текстом задачи, чтобы не открывать правку ради срока.
12. Как пользователь с открытой вкладкой, я хочу, чтобы бейдж сам сменился на OVERDUE, когда срок пройдёт, без перезагрузки страницы.
13. Как пользователь, я хочу, чтобы задача со сроком «сегодня» без времени становилась просроченной только после конца дня, а не с утра.
14. Как пользователь, я хочу поставить срок одним нажатием чипа Today, Tomorrow, This weekend или Next week, чтобы не открывать календарь.
15. Как пользователь, я хочу снять дедлайн чипом No deadline.
16. Как пользователь телефона, я хочу выбирать дату и время системным пикером, чтобы не бороться с маленьким календарём.
17. Как пользователь, я хочу, чтобы время было необязательным и добавлялось кнопкой «+ Add time», а убиралось кнопкой «Remove time».
18. Как пользователь, я хочу видеть под полями, как дедлайн будет выглядеть на карточке, чтобы проверить себя до сохранения.
19. Как пользователь screen reader'а, я хочу, чтобы у поля даты и поля времени были видимые подписи, а не только плейсхолдеры.
20. Как пользователь screen reader'а, я хочу слышать, какой чип выбран, чтобы знать, какой срок стоит.
21. Как пользователь, задававший дедлайны до R4, я хочу, чтобы мои дедлайны остались с тем же временем.
22. Как вошедший пользователь, я хочу, чтобы дедлайн без времени так же выглядел на другом устройстве, потому что признак «время задано» хранится в аккаунте.
23. Как вошедший пользователь без сети, я хочу менять дедлайн так же, как с сетью (R2).
24. Как пользователь, я хочу, чтобы дедлайн без времени переживал Complete, Undo, Move, Restore и Migration, не получая время 00:00.
25. Как пользователь List view, я хочу не видеть на карточке дату создания, потому что она мешает дедлайну (M1).
26. Как пользователь, я хочу, чтобы дедлайн не менял порядок задач в квадранте, потому что порядок задаю я.

### List view (N)

27. Как пользователь, я хочу видеть в List view четыре секции в порядке Do First, Schedule, Delegate, Eliminate, чтобы читать матрицу сверху вниз.
28. Как пользователь, я хочу видеть у секции значок 2×2 с подсвеченной ячейкой, название и критерии, чтобы узнавать квадрант не только по цвету (L1).
29. Как пользователь, я хочу видеть в заголовке секции число задач, чтобы оценить объём, не раскрывая её.
30. Как пользователь длинного списка, я хочу, чтобы заголовок секции прилипал под шапкой при прокрутке, чтобы всегда знать, в какой я секции.
31. Как пользователь, я хочу сворачивать секцию кликом по её заголовку, чтобы убрать то, что сейчас не нужно.
32. Как пользователь, я хочу, чтобы свёрнутые секции оставались свёрнутыми после перезагрузки.
33. Как пользователь, я хочу, чтобы пустая секция была раскрыта и показывала пример и «Click to add a task», как пустой квадрант.
34. Как пользователь, я хочу видеть задачи внутри секции в том же порядке, что в квадранте матрицы, чтобы не переучиваться.
35. Как пользователь, я хочу не видеть select'ов сортировки, которые я не понимал (L2).
36. Как пользователь, я хочу читать текст задач по левому краю, чтобы список легко просматривался (L3).
37. Как пользователь desktop, я хочу видеть список одной колонкой по центру, а не во всю ширину экрана.
38. Как пользователь, я хочу выделять задачу кликом или тапом и действовать через ту же панель Complete / Edit / Move to / Delete, что в матрице.
39. Как пользователь клавиатуры, я хочу, чтобы весь List view был одной остановкой Tab с тем же возвратом к последней выделенной задаче, что в матрице.
40. Как пользователь клавиатуры, я хочу ходить ↑↓ по задачам сквозь границы секций.
41. Как пользователь клавиатуры, я хочу переходить ←→ к предыдущей или следующей секции.
42. Как пользователь клавиатуры, я хочу, чтобы `1–4` переносили выделенную задачу в другую секцию, а без выделения открывали поле в ней, как в матрице.
43. Как пользователь, я хочу добавлять задачу «+» в заголовке секции или кликом по её пустому месту, как в квадранте.
44. Как пользователь, я хочу, чтобы Enter в поле добавлял задачу в конец секции и оставлял поле открытым.
45. Как пользователь, я хочу, чтобы поле в свёрнутой секции раскрывало её, чтобы видеть, куда пишу.
46. Как пользователь, я хочу, чтобы после Complete, Delete или Move фокус вставал на следующую задачу секции, как в матрице.
47. Как пользователь, я хочу снимать выделение кликом по пустому месту страницы, Esc и «×», как в матрице.
48. Как пользователь, я хочу видеть под списком строку про выделение и `?`, потому что выделение теперь работает и здесь.
49. Как пользователь телефона, я хочу, чтобы List view не пытался перетаскивать задачи и не мешал прокрутке.
50. Как пользователь, я хочу переносить задачу между секциями через Move to, раз drag в списке нет.
51. Как пользователь, я хочу, чтобы при переключении Matrix ↔ List страница открывалась сверху (L4).
52. Как пользователь, я хочу, чтобы приложение помнило выбранный вид и при следующем открытии сразу показывало его, без вспышки другого вида.
53. Как новый пользователь телефона, я хочу, чтобы по умолчанию открывалась Matrix.
54. Как пользователь screen reader'а, я хочу, чтобы секция читалась как список с именем квадранта, а её заголовок — как кнопка «развёрнуто/свёрнуто».
55. Как вошедший пользователь, я хочу, чтобы List view показывал ту же облачную матрицу, с сетью и без.

81. Как разработчик, я хочу, чтобы axe проходил в List view (сейчас падает на select'ах без подписей), с раскрытым Completed и на диалоге «Delete all».
82. Как разработчик, я хочу проверять статус и формат дедлайна таблицей с явными локалью и «сейчас», чтобы граница суток и локаль не ломались незаметно.

## Implementation Decisions

### Порядок поставки

| # | Срез | Серьёзность | Зависит от | Тикеты | Закрывает |
|---|---|---|---|---|---|
| M | Дедлайны и просрочка | S3 | F (R1) | 01–02 | M1, просрочка только цветом, datepicker на mobile |
| N | List view по секциям | S2 | F (R1), I (R3) | 03–06 | L1, L2, L3, L4, axe в List view |
| O | Completed как секция List view | S3 | N, M, E (R1) | 07–09 | C3, C4, M7, последний `window.confirm` |

- **Каждый срез — отдельный PR `ux-r4` → `main`** с проверкой на Vercel preview. Тикеты лягут в `.scratch/ux-r4/issues/`. PR открывается после последнего тикета среза: M — после 02, N — после 05 и 06, O — после 08 и 09. Первый тикет каждого среза заблокирован последним тикетом предыдущего, даже когда по коду от него не зависит: общая ветка отдаёт в PR всё, что в ней лежит.
- **Порядок M → N → O**, как в индексе аудита. M и N по коду независимы: N можно вести параллельно в ветке `ux-r4-NN` от `ux-r4` (правила `CLAUDE.md`), но в `main` они уходят по порядку.
- **O после N:** Completed — секция List view, её нет без секций N.
- **O после M:** дата завершения берёт формат M.
- Каждый срез дописывает свой раздел в [ручной чек-лист доступности](../../docs/agents/a11y-checklist.md). M правит шаг 3 основного сценария «Добавить задачу» (форма с дедлайном), O — последний пункт «Завершить задачу» (возврат из Completed). Новых axe-исключений R4 не добавляет, `KNOWN_VIOLATIONS` остаётся пустым.

### Где живёт код

По [архитектуре](../../docs/agents/architecture.md), как ориентир (тикет может решить иначе):

- статус и формат дедлайна — чистые функции сущности задачи. Бейдж — её отображение. Формат даты общий для дедлайна и даты завершения;
- поля дедлайна в форме (чипы, дата, время, превью) — часть формы задачи, общей для «New task» и правки. Если формат нужен и форме, и карточке, он живёт ниже обоих;
- признак «время задано» — поле модели `Task` и документа Firestore;
- List view — виджет матрицы. Секция использует отображение квадранта (список `listbox`, карточки, пример и CTA), а не свою копию. Выделение, панель и клавиши — существующая фича выделения, которая учится второй раскладке;
- состояние свёрнутых секций — в сохраняемом `uiStore`, рядом с `viewMode`;
- Completed — секция виджета. Строка «✓ N completed →» — виджет матрицы. Диалог «Delete all» — на общем модальном компоненте. Унаследованные `entities/completedTasksAccordion`, `ListTaskItem` и страничный `CompletedTasks` O и N переписывают, поэтому старые места удаляются в тех же срезах.

### M. Дедлайны и просрочка

Решения: [тикет 15](../ui-ux-audit/issues/15-deadlines-overdue.md), карточка из варианта B и форма из варианта A прототипа (`prototype/deadlines`, `d0b4166`, скриншоты `walkthrough/proto-15-*.png`).

**Модель** (дополнение спеки).

- В `Task` добавляется необязательный признак «время задано» (`hasDueTime`, имя решает тикет). Дедлайн без времени хранится как местная полночь этого дня (00:00) с признаком `false`.
- Задача без признака считается задачей со временем. Все дедлайны до R4 заданы `react-datepicker` или пресетами +3h и т. п., у них время есть всегда. Миграции данных нет.
- Документ Firestore получает то же поле. Облачный клиент пишет его вместе с `dueDate` и читает отсутствующее как «время есть». Ключи localStorage и прочая схема не меняются.
- Признак переживает все действия стора: правку, Complete, Undo, Move, Restore, удаление с Undo и Migration (план Migration переносит поля задачи как есть).

**Статус.** Чистая функция «дедлайн, признак времени, сейчас → статус». Всё считается по местному календарю.

- **Overdue:** со временем — сейчас позже дедлайна; без времени — сегодня позже дня дедлайна, то есть после 23:59:59 этого дня.
- **Due today:** день дедлайна — сегодня и срок не прошёл. Задача со временем 9:00 в 10:00 того же дня уже Overdue.
- **Due soon:** день дедлайна — завтра или послезавтра.
- Дальше статуса нет. Без дедлайна статуса нет.

**Когда статус обновляется** (дополнение спеки). Статус пересчитывается раз в минуту и когда вкладка снова становится видимой. Так OVERDUE и смена дня наступают без перезагрузки. Часы — одни на страницу, а не таймер на каждую карточку.

**Формат даты.** Чистая функция «дата, признак времени, сейчас, локаль → строка».

- День недели коротко, число, месяц коротко: `Fri 25 Sept` (en-GB).
- Год — только если он не текущий: `Fri, 29 Oct 2027`.
- Время — только если задано: `Fri 25 Sept, 9:00`, в en-US `Fri, Sep 25, 9:00 AM`.
- Локаль и 12/24 часа берутся из браузера через `Intl` (локаль по умолчанию), а не зашиты. Точная пунктуация — какую даёт `Intl` для локали, её тесты не фиксируют (дополнение спеки).
- Относительное время («in 3 days», «2 hours overdue») и `title` с `dd/MM/yyyy HH:mm` уходят.

**Карточка** (матрица, телефон, квадрант во весь экран, List view).

- Под текстом строка дедлайна: бейдж статуса словом, затем дата. `⚠ OVERDUE`, `DUE TODAY`, `DUE SOON`. Знак `⚠` декоративный, screen reader его не читает.
- Статус читается текстом. У OVERDUE бейдж с заливкой и толстая левая полоса у карточки, у остальных бейджей своя приглушённая заливка. Цвет только усиливает слово.
- Screen reader слышит строку дедлайна вместе с задачей: `option` содержит текст задачи, статус и дату (дополнение спеки: например «Pay rent, OVERDUE, Fri 25 Sept»). Отдельного `aria-label` у бейджа нет.
- Контраст текста бейджа и даты не меньше 4.5:1 на фонах всех квадрантов в обеих темах, полоса OVERDUE не меньше 3:1 к фону карточки.
- Дата создания уходит и с карточки List view (M1). В матрице её уже нет.
- Порядок задач дедлайн не меняет. Автоподъёма просроченных и подсказки «Move to Do First» нет.

**Форма** («New task» и правка, одна форма).

- Группа «Deadline» с видимой подписью. В ней чипы No deadline / Today / Tomorrow / This weekend / Next week. Каждый ставит дату без времени и убирает время, если оно было. No deadline снимает дедлайн.
- **Даты чипов** (дополнение спеки):
  - Today — сегодня;
  - Tomorrow — завтра;
  - This weekend — ближайшая суббота, а в субботу и воскресенье — сегодня;
  - Next week — понедельник следующей недели.
- Выбранный чип отмечен `aria-pressed="true"`. Выбранным считается чип, чья дата совпадает с датой в поле и время не задано. После ручной правки даты или времени ни один чип может не быть выбран. No deadline выбран, когда дедлайна нет. Чипы — кнопки с подписью, цель не меньше 44×44 на телефоне.
- Ниже нативный `<input type="date">` с видимым `<label>` «Date». Ввод даты вручную ставит дедлайн без времени.
- Кнопка «+ Add time» открывает нативный `<input type="time">` с видимым `<label>` «Time» и кнопкой «Remove time». Фокус после «+ Add time» — в поле времени, после «Remove time» — на «+ Add time» (дополнение спеки). Время по умолчанию при открытии — 9:00 (дополнение спеки: у прототипа A так).
- Под полями строка-превью «Shows on card as: …» тем же форматом и тем же бейджем, что на карточке. Без дедлайна превью нет. Превью — обычный текст, не live-регион.
- Дата в прошлом допустима: задача сразу станет Overdue. Пустое поле даты при выбранном времени снимает время (без даты времени нет).
- Сохранение по Enter в поле текста и прежняя валидация текста не меняются. Ошибка «неверная дата» остаётся для невалидного ввода в поле даты.
- `react-datepicker`, его типы, `datepicker.css`, пресеты +3h / +24h / +3d / +1w и переключатель «есть дедлайн» уходят. `date-fns` остаётся, если его ещё что-то использует.

**Вошедший пользователь.** Правка дедлайна — обычная запись стора, без сети уходит в Pending changes (R2).

### N. List view по секциям

Решения: [тикет 10](../ui-ux-audit/issues/10-list-view-role.md), вариант C прототипа [Мобильная матрица](../ui-ux-audit/issues/06-mobile-matrix.md) (`prototype/mobile-matrix`, `?variant=C`, `walkthrough/proto-06-C.png`); семантика — [тикет 11](../ui-ux-audit/issues/11-accessibility-baseline.md).

**Раскладка.**

- Одна колонка по центру (`max-w-2xl`) на всех ширинах. Четыре секции в порядке Do First, Schedule, Delegate, Eliminate.
- **Заголовок секции** липкий: прилипает под шапкой и полосой синхронизации (`--top-bars-height` из R3), следующий заголовок выталкивает предыдущий. В нём:
  - значок 2×2 с подсвеченной ячейкой квадранта, декоративный;
  - название и критерии подзаголовком из словаря квадрантов;
  - счётчик активных задач;
  - «+», как в заголовке квадранта.
- Заголовок — `h2` с кнопкой внутри. Кнопка сворачивает и раскрывает секцию, у неё `aria-expanded` и `aria-controls` на список секции. Доступное имя «Do First, 3 tasks» (для одной — «1 task») (дополнение спеки: счётчик в имени, критерии как описание). Кнопки заголовков — обычные остановки Tab, «+» как в матрице вне Tab-порядка.
- **Список секции** — `listbox` с именем квадранта («Do First»), задачи — `option` с `aria-selected`, как в квадранте матрицы. Карточка та же, что в матрице (текст и строка дедлайна M), текст по левому краю, без ограничения строк.
- **Пустая секция** всегда раскрыта и показывает пример и «Click to add a task» / «Tap to add» из I. У её заголовка кнопки сворачивания нет, только `h2` с названием (дополнение спеки). Сохранённое «свёрнуто» возвращается, когда в секции появится задача.
- **Свёрнутая секция** показывает только заголовок, её список не рендерится.
- Сворачивание запоминается на устройстве в сохраняемом `uiStore`, по квадранту. Не синхронизируется, вход и выход его не сбрасывают. По умолчанию все секции раскрыты.
- При `prefers-reduced-motion` сворачивание мгновенное, иначе можно короткий fade или высоту.

**Порядок.** Задачи в секции в том же порядке, что в квадранте. Select'ы «Sort by» и «Order», `sortField`, `sortDirection` и их действия удаляются. Старые ключи в сохранённом `uiStore` просто игнорируются.

**Выделение и действия** — как в матрице ([тикет 05](../ui-ux-audit/issues/05-task-actions-discoverability.md)):

- клик или тап выделяет задачу, повторный клик, клик по пустому месту страницы, Esc и «×» снимают (Q из R3);
- снизу та же панель Complete / Edit / Move to / Delete / «×», на телефоне телефонный вариант;
- те же клавиши: Enter или E — правка, C или Space — Complete, Delete/Backspace — Delete, `1–4` с выделением — Move, без выделения — поле в секции, `N` — поле, `?` — шпаргалка, `Ctrl/Cmd+Z` — Undo. Точный набор — какой уже есть в матрице;
- фокус после Complete, Delete и Move: следующая задача секции, иначе предыдущая, иначе «Add a task» опустевшей секции. После Undo — восстановленная задача;
- Move в свёрнутую секцию переносит задачу молча для раскладки: секция остаётся свёрнутой, toast «Moved to …» с Undo как в матрице (дополнение спеки);
- строка под матрицей из I («Click a task to select it · ↑↓←→ move selection · ? all shortcuts» / «Tap a task to select it») показывается и под List view.

**Клавиатура в списке** (дополнение спеки).

- Весь список задач — одна остановка Tab с roving tabindex, как матрица. Tab выделяет последнюю выделенную задачу, если она видна, иначе первую задачу первой раскрытой секции, иначе «Add a task» первой пустой.
- **↑↓** идут по задачам сквозь границы секций в порядке Do First → Eliminate. Свёрнутые секции пропускаются, «Add a task» пустой секции — такая же остановка, как задача. На первой и последней остановке стрелка никуда не ведёт, без кольцевого перехода.
- **←→** переходят к первой задаче предыдущей или следующей раскрытой секции, в пустой — на её «Add a task». Свёрнутые пропускаются.
- Фокус на кнопке заголовка секции не выделяет задачу. Стрелки там не перехватываются, Enter и Space сворачивают.
- **Свернуть секцию с Selected Task** — снять выделение, фокус остаётся на кнопке заголовка.
- **Инлайн-поле в свёрнутой секции** («+», `N`, `1–4`) раскрывает её и открывает поле в конце списка. Раскрытие запоминается, как при клике по заголовку.

**Добавление** — как G в R3: «+» в заголовке, клик по пустому месту секции (после последней задачи и в промежутках), `N` и `1–4` открывают инлайн-поле «Add task to <квадрант>» в конце секции. Enter добавляет и оставляет поле, Esc закрывает. Поле одно на странице, текст переезжает между секциями.

**Drag в списке нет.** Список монтируется без сенсоров drag. Перенос — Move to и `1–4`, ручной порядок меняется только в матрице. На телефоне нет раскрытия секции на весь экран: List view и так одна колонка.

**Переключение вида.**

- При смене Matrix ↔ List страница прокручивается наверх, сразу, без плавной прокрутки (L4). Исключение — строка «✓ N completed →» из O.
- Смена вида, как и в R3, снимает выделение и закрывает поле.
- Выбранный вид запоминается на устройстве (`viewMode` в сохраняемом `uiStore` уже есть). По умолчанию, и на телефоне тоже, Matrix.
- **Без вспышки** (дополнение спеки, долг тикета 14 R3). Серверный HTML не знает сохранённого вида. Пока `uiStore` не прочитан из localStorage, область вида показывает лоадер, как при загрузке аккаунта, а вкладки не рисуют выбранную (место под ними зарезервировано, чтобы шапка не прыгала). После чтения сразу показывается сохранённый вид. Разметка `tablist` с `aria-selected` у одной вкладки восстанавливается в тот же кадр.

**Что уходит:** ленточная раскладка List view, `ListTaskItem` с собственными кнопками и датой создания, сортировки. Пока нет O, блок Completed остаётся под списком, как под матрицей.

**Вошедший пользователь:** секции читают ту же текущую матрицу, что Matrix. Холодный старт без сети (R2): пустые секции без примеров, как пустые квадранты.

### O. Completed как секция List view

Решения: [тикет 14](../ui-ux-audit/issues/14-completed-section.md); диалог — [тикет 04](../ui-ux-audit/issues/04-destructive-actions.md); toast Restore и ошибка «Delete all» — [тикет 12](../ui-ux-audit/issues/12-toast-behaviour.md).

**Секция.**

- Последняя секция List view «Completed (N)», N — число завершённых задач. Без завершённых задач секции нет.
- По умолчанию свёрнута. Сворачивание запоминается так же, как у секций N. Заголовок липкий, как у остальных, без значка 2×2 и без «+».
- Кнопка заголовка: доступное имя «Completed, 12 tasks», `aria-expanded`. Рядом в заголовке кнопка «Delete all», видимая только у раскрытой секции (дополнение спеки: у свёрнутой её легко нажать мимо).
- Список — `listbox` «Completed», строки — `option` с `aria-selected`.
- Блок `CompletedTasksAccordion` под матрицей и его автопрокрутка при раскрытии уходят.

**Строка в Matrix.**

- Под матрицей и строкой подсказки из I — кнопка «✓ N completed →» (для одной «✓ 1 completed →»). Без завершённых её нет.
- Клик переключает вид на List, раскрывает Completed (и запоминает это), прокручивает к её заголовку и ставит фокус на кнопку заголовка. Вместо прокрутки наверх из N (дополнение спеки).
- Контраст текста ≥ 4.5:1, цель 44×44 на телефоне.

**Порядок и объём.**

- Новые сверху, по `completedAt`, для обоих Storage. Complete кладёт задачу в начало Completed, Undo Restore возвращает её на прежнее место. Облачный снимок уже сортирует так.
- Показываются первые 50. Под ними «Show more» добавляет следующие 50, пока задачи не кончатся. Сколько показано, не запоминается: после перезагрузки снова 50 (дополнение спеки). После «Show more» фокус на первой из новых задач.
- Группировки по дням и автоочистки нет.

**Строка завершённой задачи.**

- Текст задачи (зачёркнутый приглушённо, контраст всё равно ≥ 4.5:1), подпись исходного квадранта словом («Schedule») и «Completed Thu 24 Sept, 8:30» форматом M со временем. Дата создания не показывается совсем. Дедлайн и бейдж у завершённой задачи не показываются.
- Приглушённый цвет квадранта — только дополнительный признак.
- Задача без исходного квадранта (данные до R1) подписана квадрантом, куда её вернёт Restore (сейчас `RESTORE_FALLBACK_QUADRANT`).
- Кнопок на строке нет, иконки по hover уходят.

**Выделение и действия** — «выбери, потом действуй».

- Клик или тап выделяет завершённую задачу. Снизу панель Restore / Delete / «×» с подписью «Actions for “<текст>”», те же desktop- и телефонный варианты.
- Клавиши: Delete/Backspace — Delete, `Ctrl/Cmd+Z` — Undo, Esc и «×» снимают выделение. `1–4`, C, Space, E, Enter и `N` на завершённой задаче не действуют (дополнение спеки: клавиши Complete и Edit тоже, раз этих действий нет). Отдельной клавиши Restore нет.
- Completed входит в roving tabindex List view: ↑↓ продолжают из последней задачи Eliminate в первую завершённую и обратно, ←→ считают Completed последней секцией. Свёрнутая Completed пропускается.
- **Restore** — задача уходит в начало исходного квадранта. Toast «Restored to Schedule» с Undo (уже есть в модуле отмены). Undo возвращает её в Completed на прежнее место, фокус на ней.
- **Delete** — сразу, toast «Task deleted» с Undo, без `window.confirm`. Undo возвращает на прежнее место, фокус на ней.
- **Фокус после Restore и Delete:** следующая завершённая задача, иначе предыдущая. Если Completed опустела и секция исчезла — последняя задача последней раскрытой секции, иначе контейнер List view (как правило J1 для матрицы) (дополнение спеки). На `body` фокус не падает.

**«Delete all».**

- Нативный `<dialog>` на общем модальном компоненте. Заголовок «Delete all 12 completed tasks?» (для одной — «Delete 1 completed task?»). Пояснение «This can't be undone.». Кнопки «Delete all» и «Cancel». Фокус при открытии на «Cancel», потому что действие необратимо (дополнение спеки).
- «Delete all» удаляет все завершённые задачи (в облаке — batch, как сейчас). Undo нет (решение тикета 04). Диалог закрывается, секции Completed больше нет, фокус по правилу «Completed опустела».
- Esc и «Cancel» закрывают без изменений, фокус на «Delete all» в заголовке.
- Сбой — «Couldn't delete. Try again» внутри диалога (`role="alert"`), диалог не закрывается, кнопка снова доступна. Для вошедшего запись уходит в Pending changes и без сети не сбоит (R2). Сбоем считается только исключение действия стора, отказ облака идёт в полосу Sync error.
- После O `window.confirm` в приложении не вызывается нигде.

**Вошедший пользователь:** Restore, Delete и «Delete all» — обычные записи стора, без сети копятся в Pending changes (R2).

## Testing Decisions

**Что такое хороший тест.** Как в R1–R3:

- тест проверяет только внешнее поведение — что видит и делает пользователь и что слышит screen reader (роли, доступные имена, тексты, фокус);
- во внутреннее состояние сторов, имена хуков и ключи localStorage тесты не лезут. Запоминание проверяется через `reload()`, а не чтением ключа;
- собственные модули не мокаются, поиск идёт по ролям и именам;
- мокаются только внешние границы: облачный клиент матрицы, клиент аутентификации, роутер, `matchMedia`, часы (`jest.useFakeTimers` + `setSystemTime`).

**Seams (согласованы).**

1. **Главный seam — смонтированная главная** (`renderHomePage` с фейком облака из R2). Новых границ R4 не вводит. Расширения:
   - **«сейчас»** задаётся `jest.setSystemTime` до монтирования, отдельной опции нет. Пересчёт статуса проверяется `jest.advanceTimersByTime`;
   - **сид задачи** с дедлайном принимает признак «время задано». Задача-строка остаётся без дедлайна, как сейчас;
   - **завершённые задачи** уже сидятся опцией `completedTasks`, порядок сида — любой, приложение сортирует само;
   - **прокрутка** проверяется шпионом `window.scrollTo` и `scrollIntoView`, раскладки jsdom не делает.

   Формат даты главная проверяет только тем, что строка дедлайна содержит слово статуса и дату (по той же функции формата или по числу дня), без привязки к локали Node.
2. **Тонкий seam — чистые функции дедлайна.** Статус («дедлайн, время задано, сейчас → overdue | today | soon | none») и формат («дата, время задано, сейчас, локаль → строка») проверяются таблицей, как `actionChanges` в R2 и план Migration в R3. Случаи:
   - со временем: за минуту до срока и через минуту после;
   - без времени: в 00:00, 12:00 и 23:59 дня дедлайна — Due today, в 00:00 следующего — Overdue;
   - завтра и послезавтра — Due soon, через три дня — без статуса;
   - вчера без времени — Overdue;
   - задача без признака (до R4) считается со временем;
   - формат в en-GB, en-US и de-DE: день недели, число, месяц; год только не в текущем; время только если задано; 12/24 часа по локали;
   - переход через Новый год (Due soon 31 декабря для 1 января, год в дате следующего года).

   Даты чипов («This weekend» в пятницу, субботу и воскресенье, «Next week» в воскресенье и понедельник) — в той же таблице, если тикет вынесет их в чистую функцию, иначе на главном seam.

Других seams нет. Форма, секции, Completed и диалог проверяются только главным seam, отдельных компонентных тестов нет.

## Out of Scope

- Сортировка или группировка по дедлайну, автоподъём просроченных, подсказка «Move to Do First» (отклонены в тикете 15).
- Дедлайн в инлайн-поле добавления: дедлайн задаётся формой «New task» или правкой, как в R3.
- Напоминания и уведомления о сроке, повторяющиеся задачи, часовые пояса дедлайна (дедлайн без времени привязан к местному дню устройства).
- Drag в List view и ручной порядок в нём (тикет 10).
- Третий сегмент Completed в шапке, Completed под матрицей на всех ширинах, группировка Completed по дням, автоочистка (отклонены в тикете 14).
- Отменяемый «Delete all» (отклонён в тикете 04).
- Поиск и фильтры по задачам.
- Analytics и `/eisenhower-matrix` сверх того, что меняет формат дат (цель a11y для них — «по мере сил»).
- Правила безопасности Firestore (см. Further Notes R2).

## Further Notes

- **Серьёзность:** N — S2 (L1 — квадрант только цветом, axe падает в List view), M и O — S3. Порядок M → N → O взят из индекса аудита. Потерь данных R4 не закрывает. Но M меняет схему документа, поэтому чтение без признака «время задано» проверяется и в таблице, и на главном seam.
- **Схема Firestore.** Новое поле необязательное и пишется только новым кодом. Старый клиент (вкладка, открытая до деплоя) его не пишет, и дедлайн без времени, сохранённый такой вкладкой, получит время. Это принятая цена: окно короткое, данных не теряется.
- **Дедлайн без времени и часовые пояса.** Он хранится как местная полночь. Если пользователь сменит часовой пояс, день может сдвинуться на один. Хранить отдельную строку даты `YYYY-MM-DD` было бы точнее, но меняет смысл `dueDate` для всего кода и облака. Если это окажется проблемой, это отдельный тикет.
- **N — самый объёмный срез.** Фича выделения сейчас знает только раскладку 2×2: стрелки считают соседей по строке сетки. N учит её второй раскладке (секции подряд) и свёрнутым секциям. Имеет смысл нарезать N так, чтобы сначала шли секции с раскладкой, сворачиванием и без сортировок (карточки пока без выделения, как сейчас `ListTaskItem`), затем выделение, панель и клавиши, затем добавление, затем «без вспышки» и прокрутка наверх. PR в `main` — после всего среза.
- **Переход «✓ N completed →»** — единственное место, где смена вида не прокручивает наверх. Если тикет N реализует прокрутку наверх внутри действия смены вида, O добавляет ему явное исключение, а не второй путь смены вида.
- **Возможные расхождения с R1–R3**, которые срезы меняют сознательно:
  - относительный бейдж дедлайна R1 → абсолютная дата и статус (M);
  - «Completed показывается под списком так же, как под матрицей» из тикета 10 → Completed — секция List view (O, по тикету 14);
  - `setViewModeAction` по-прежнему снимает выделение, но теперь выделение есть в обоих видах (N);
  - Restore в начало квадранта, а не в конец (O).

  Тесты и чек-лист предыдущих релизов по этим пунктам обновляются в своих срезах.
- ADR в репозитории нет (`docs/adr/` отсутствует), противоречий нет. Термины глоссария хватает: **Deadline**, **Overdue**, **Completed Task** и **List view** уже описаны в `CONTEXT.md`. «Секция» — деталь UI List view, а не понятие предметной области.

# Архитектура: Feature-Sliced Design

Код в `src/` разложен по [Feature-Sliced Design](https://feature-sliced.design/). Этот документ — правила для нового кода и для кода, который тикет всё равно трогает. Существующее отклонение от правил само по себе не повод для рефакторинга в рамках тикета (см. «Унаследованное» внизу).

Алиас: `@/` → `src/`.

## Слои

Импорты идут только вниз: слой не импортирует из слоя выше и из соседнего слайса своего слоя.

```
app/        FSD-слой приложения: корневой layout, провайдеры, глобальные стили, тестовый seam (src/app/tests)
pages/      экраны — тонкие композиции виджетов и фич
widgets/    крупные самостоятельные блоки UI (матрица целиком, шапка)
features/   действия пользователя (добавить задачу, выделить и действовать, отменить, войти)
entities/   объекты предметной области и их отображение (Task, Quadrant)
shared/     инфраструктура без знания о продукте: UI-кит, хуки, утилиты, конфиг, API-клиент, сторы
```

**Роуты Next.js** живут в корневом `app/` (не `src/app/`). Файл роута только реэкспортирует страницу из `src/pages` как `default` и объявляет `metadata`:

```ts
export { EisenhowerMatrixPage as default } from '@/pages/eisenhowerMatrix';
export const metadata: Metadata = { … };
```

Логики, разметки и импортов из других слоёв в файлах роутов нет.

### Куда класть новое

Идём сверху по вопросам, первый «да» решает:

1. Это действие пользователя со своим поведением (клик, клавиша, отмена)? → `features/<action>`
2. Это блок экрана, собирающий несколько фич и сущностей? → `widgets/<block>`
3. Это отображение или модель объекта предметной области без сценария действия? → `entities/<object>`
4. Это не знает ни о задачах, ни о квадрантах (кнопка, диалог, toast-контейнер, `useMediaQuery`)? → `shared/<segment>`

Слова предметной области берутся из `CONTEXT.md`: слайс называется по термину глоссария (`task`, `quadrant`, `selectedTask`), а не по технике (`dndWrapper`, `helpers`).

Примеры для R1 (ориентир, а не закон — если тикет или спека решают иначе, прав тикет):

| Что | Куда | Почему |
|---|---|---|
| Контейнер toast, кнопка Undo как UI | `shared/ui/toast` | не знает о задачах |
| Модуль отмены с одним слотом («выполни, покажи toast, вот как откатить») | `features/undo` | сценарий пользователя, используется матрицей, List view и Completed |
| Selected Task: состояние выделения, панель действий, клавиши | `features/selectTask` (или по термину из тикета) | действие пользователя поверх задач |
| Карточка задачи, бейдж дедлайна | `entities/task` | отображение объекта предметной области |
| Словарь квадрантов | `shared/consts/quadrants.ts` | уже так (тикет 02) |
| Матрица целиком | `widgets/taskMatrix` | собирает фичи и сущности |

## Слайс изнутри

Создавай только нужные сегменты:

```
sliceName/
├── ui/            главный компонент(ы) слайса: SliceName.tsx + index.ts
├── components/    приватные подкомпоненты слайса (не экспортируются наружу)
├── model/         состояние: zustand-стор или хук состояния
├── hooks/         хуки слайса, не являющиеся моделью
├── lib/           чистые функции, по файлу на функцию + index.ts
├── consts/        константы и enum'ы слайса (index.ts)
├── types/         типы слайса (index.ts)
├── api/           запросы к Firebase и обёртки над ними
└── index.ts       PUBLIC API слайса
```

### Public API

- Снаружи слайс импортируется **только через корень**: `@/entities/matrixLayout`, не `@/entities/matrixLayout/components/taskItem`. Это проверяет ESLint (`no-restricted-imports` в `eslint.config.mjs`), нарушение валит pre-commit.
- `index.ts` экспортирует только то, что реально нужно снаружи, именованными экспортами:

  ```ts
  export { TaskMatrix } from './ui';
  export { useSelectedTask } from './model';
  export type { SelectedTaskState } from './types';
  ```

- Внутри слайса импорты относительные (`./ui`, `../lib`), алиас на свой же слайс не используется: иначе получаются циклы через `index.ts`.
- Внутри `shared` импорт на уровне сегмента или модуля сегмента допустим: `@/shared/ui/modal`, `@/shared/consts/quadrants`, `@/shared/stores/tasksStore`.

### `components/`

- `components/` — приватные подкомпоненты **одного** слайса. Каждый — папка со своим `index.ts` (`components/QuadrantHeader/index.ts`), внутри может быть свой `ui/`, `lib/`, `consts/`.
- **Без рекурсии:** внутри `components/<Sub>/` не бывает ещё одного `components/`. Если подкомпоненту нужны свои подкомпоненты, он либо кладёт их рядом плоско в тот же `components/`, либо это сигнал, что он вырос в отдельный слайс.
- Подкомпоненты из `components/` не реэкспортируются из корня слайса. Если он понадобился снаружи — это уже public API: переноси в `ui/` или в отдельный слайс.

### Когда выносить в `shared`

Компонент, хук или утилита нужны в двух и более несвязанных слайсах → в `shared`. Пока нужен в одном — живёт в этом слайсе.

## Стиль кода

- Компоненты — стрелочные функции, именованный экспорт. `default` export только там, где его требует Next.js (файлы роутов в корневом `app/`).
- Один файл — одна ответственность: хук, маппер и компонент в разных файлах.
- Стили — Tailwind-классы в JSX; условные и сливаемые классы через `twMerge` из `tailwind-merge`.
- Состояние: локальное (`useState`) по умолчанию; zustand — для состояния, которое делят несколько слайсов.

## Унаследованное

В коде есть места, которые правилам выше не соответствуют: сегмент `components/` в `entities/matrixLayout` фактически содержит сущности (`taskItem`, `quadrant`), доменные сторы — в `shared/stores`, часть слайсов без `ui/index.ts`. Тикет **не** переносит такой код, если его сценарий этого не требует. Если тикет всё равно переписывает модуль, новый код кладётся по правилам этого документа, а старое место удаляется в том же тикете.
